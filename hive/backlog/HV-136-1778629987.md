## Goal

Replace FS-028's `/join`, `/leave`, `/heartbeat`, `/whoami` endpoints, the heartbeat process, the role-cache check hook, and the tenure-based role override with **one long-lived SSE stream per bot**, where the open TCP socket is the liveness signal.

## Why

FS-028 failed on first multi-bot use (2026-05-12). One operator session surfaced three bugs:

- **B1 — seat clobber**: a second bot's `/join` evicted the first bot's row. `/colony` returned only the second bot at seat 1 before the first re-ran whoami.
- **B2 — silent heartbeat failure**: `Start-Job -FilePath ./scripts/heartbeat.ps1` returned without writing `.bot-hive-heartbeat.pid`. The liveness signal never started; server had no way to know.
- **B3 — three sources of truth for role**: `.bot-hive-identity role=pm` is local-only. Whoami prints role=PM; `/colony` derives role from seat via the table; the modal shows the derived role. The identity file, the DB, and the role table disagreed in the same session.

Root cause is structural, not behavioral: liveness via heartbeat + sweep, role via seat-derivation + local override, and lifecycle split across four endpoints means every state transition has multiple authorities that drift. Collapse the authority surface to one stream and the drift cases disappear.

## Done when

- One endpoint: `GET /api/bots/stream?project=X&colony=Y&handle=Z` (SSE).
  - On **open**: insert/rebind a row in `bots`; assign `seat = max(seat)+1`; re-derive role for every active row in the colony via the existing `roleForSeat(N, seat)` table; broadcast colony snapshot to project subscribers; send `your-role: <derived>` to the new connection as the first event.
  - On **close**: hold the row for **15 s**. If the same `(colony, handle)` reopens within the window, no-op (re-bind `connection_id`). After 15 s, delete the row, renumber survivors so seats stay 1..N, re-derive roles, push `your-role: <new>` to any bot whose role changed, broadcast snapshot.
- All write paths inside one transaction holding the existing per-`(project, colony)` advisory lock.
- `bots` schema: keep `seat`, `role`; add `connection_id` (text, last-writer-wins on reopen); drop `status`, `last_heartbeat_at`.
- Server stores `bots.role` verbatim from the re-derive step. No separate fallback path. No `.bot-hive-identity role=` override.
- Bot side: one script — `scripts/stream.{sh,ps1}` — opens the SSE, writes `.bot-hive-role-notice` on each `your-role:` event, exits if reconnect fails after N=3 retries with exponential backoff.
- `UserPromptSubmit` hook keeps the existing wiring but reads `.bot-hive-role-notice` (one-shot: read + delete) instead of running `check-role`.
- Spawn flow (`src/app/projects/[id]/add-bot-spawn-command.ts`) stops writing `role=` to `.bot-hive-identity`.
- Bootstrap (`hive/bot-startup.md`): "start `stream.ps1` in background; wait for first `your-role:`; announce; delete kickoff marker; stop." No `/whoami` round-trip.
- Shutdown (`hive/bot-shutdown.md`): "close the SSE stream and exit." No `/leave` call.

## Desired output

Walked end-to-end against the 0 → 5 → 0 lifecycle (verified before filing):

- **Spawn 1 (`buzz`)**: announces "I'm allavallc.buzz, seat 1, role PM + coder + tester, ready." Modal shows buzz alone.
- **Spawn 2 (`wren`)**: wren announces "seat 2, coder". Buzz's next prompt yields "role now PM + tester." Modal shows both.
- **Spawn 3 (`scout`)**: scout announces "seat 3, tester". Buzz's next prompt yields "role now PM." Modal shows three.
- **Spawn 4 (`kestrel`)**: kestrel announces "seat 4, coder (additional)". No other bots change.
- **Spawn 5 (`falcon`)**: falcon announces "seat 5, coder (additional)". No other bots change.
- **Remove buzz** (seat 2 — middle): wren stays seat 1 PM. scout 3→2 flips tester→coder. kestrel 4→3 flips coder→tester. falcon 5→4 stays coder. Three role-change announcements on next prompts.
- **Remove wren** (seat 1, the PM): scout 2→1 becomes PM. kestrel 3→2 stays coder. falcon 4→3 becomes tester. Three role-change announcements.
- **Remove falcon** (seat 3, tail): scout's next prompt yields "role now PM + tester." kestrel unchanged.
- **Remove kestrel**: scout's next prompt yields "role now PM + coder + tester."
- **Remove scout**: colony empty. Modal empty.

## Success signals

- `GET /api/bots/colony` returns exactly the set of bots with currently-open SSE streams. No stale rows.
- Spawning 5 bots and removing in arbitrary order leaves every survivor's `(seat, role)` matching `roleForSeat(N, seat)` from `src/lib/roles.ts`.
- No `.bot-hive-heartbeat.pid` or `.bot-hive-role-cache` files exist anywhere in the working tree.
- No `join`, `leave`, `heartbeat`, `whoami` route files in `src/app/api/bots/`.
- Modal seat strip updates within ~1 s of any add/remove. Bot's chat announcement updates within ~1 prompt of any role change.

## Failure signals

- A bot's terminal closes but `/colony` shows the row past 30 s — `onClose` handler not firing, or grace period misconfigured.
- Two bots both think they're seat 1 — advisory lock not held across re-derive, or transaction boundary wrong.
- A 2-second network blip churns the colony (other bots get spurious role-change notices) — grace period not respected.
- Operator sees mismatched roles between a bot's chat announcement and the "See Bot Team" modal — server didn't push the right `your-role:` to that bot, or `stream.ps1` didn't write the notice, or the hook didn't surface it.
- `.bot-hive-role-notice` accumulates instead of being one-shot — hook isn't deleting after reading.

## Tests

- **Unit (Vitest, no DB)**: pure functions for `nextSeat(activeSeats)`, `renumberAfterDelete(seats, departedSeat)`, `derivedRoles(N)` driven by the `roleForSeat` table. Cover 0→5 grow path and 5→0 shrink path with both tail and middle removals.
- **Integration (transactional fixture)**: parallel spawn of 3 SSE clients, close the middle; assert all remaining rows have correct seat + role within one DB tick.
- **Integration (grace period)**: open → close → reopen within 15 s. Assert row was never deleted and no broadcast fired.
- **Integration (grace period)**: open → close → wait 16 s. Assert row deleted, snapshot broadcast fired, surviving bots received `your-role:` only if their role changed.
- **Integration (connection_id rebind)**: open conn1, open conn2 for same (colony, handle); assert conn1's writes to the stream silently drop and conn2 is canonical.
- **E2E (manual, on prod)**: scripted walkthrough below.

## How to test

1. Spawn bot 1 via Add-a-Bot. Expect announcement `PM + coder + tester`. Open "See Bot Team" — one row.
2. Spawn bot 2. Expect bot 2 to announce `coder`. Type any prompt in bot 1's window — expect "role now PM + tester."
3. Repeat for bots 3, 4, 5. After bot 3, expect bot 1 to demote to `PM` and bot 2 to stay `coder` and bot 3 to announce `tester`. Bots 4 and 5 should announce `coder (additional)` with no other bot changing.
4. Close bot 2's terminal tab. Wait ~16 s. Type a prompt in bots 1, 3, 4, 5 — at least bot 1 and one of 3/4 should announce a role change consistent with the table.
5. Close bot 1's terminal tab (the PM). Wait ~16 s. Type a prompt in surviving bots — the new seat-1 should announce "role now PM …".
6. Close remaining bots in any order. Modal should empty out within ~1 s of each close (after grace).
7. **Network blip test**: in any 2-bot state, briefly disable Wi-Fi for 5 s on the bot 2 machine. Bot 2 should reconnect, bot 1 should see no role change.
8. **Identity file**: open a fresh worktree's `.bot-hive-identity` after spawn. Expect `colony=` and `handle=` only — no `role=` line.

## Notes

- **Supersedes the seat-as-source-of-truth design from HV-130/131/133/134/135.** Those tickets are done; this is the next iteration after first-use revealed three bugs (B1, B2, B3). The current FS-028 feature-set file stays active under the same name; the redesign lives here.
- **Middle-removal flips surviving roles.** Removing seat 2 in a 4-bot colony promotes seat 3 to seat 2 (which the table maps to a different role). Behavior is correct per the table; will feel sudden in chat. Acceptable.
- **Reconnect-within-grace-period** absorbs TCP blips. 15 s chosen as a compromise: short enough that a closed terminal feels instant, long enough to survive a captive-portal blip.
- **`connection_id` last-writer-wins**: if two physical processes ever race the same `(colony, handle)`, the later open replaces the row's `connection_id`. The earlier one's writes to the stream silently drop. Cheap, no auth needed in v1.
