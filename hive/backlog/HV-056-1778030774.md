## Goal
When a bot is actively working on a ticket, that ticket visibly appears in the **In-Progress** column on the live board — for the entire duration of the work, not invisibly inside a branch. Today the board reads from `main` and the convention "one PR per ticket lifecycle" means tickets transition `backlog → in-review` via a single squashed commit, with the in-progress phase only existing on the bot's working branch (invisible to the board).

## Why
Live observation today (2026-05-06): humans on the board could not tell what either bot was working on. Both bots' tickets jumped from `backlog` directly to `in-review` because the work-PR includes the ticket move-to-in-review in the same commit. The In-Progress column stayed empty even while both bots worked for hours.

This breaks the board's primary value: *visible swarm activity*. The whole point of a kanban is "who's working on what right now." Right now the kanban can't answer that.

## Done when

A non-trivial design choice — pick one (or both):

### Option A: Make claim-PR REQUIRED, not optional

Currently HV-031's convention says: "The optional claim-PR is the allowed exception." That made claim-PRs a lazy path. Tighten:

- Whenever a ticket's expected work is >5 minutes (rule of thumb), the bot MUST open a claim-PR first. The claim-PR is small (just the folder move + status field updates), auto-merges in ~2 min, and makes the in-progress state visible on main.
- The work-PR is then based on a main where the ticket is already in `in-progress/`.
- AGENTS.md and HIVE.md updated accordingly.

Pro: visible state on the board. Con: ~2 min of CI ceremony per ticket.

### Option B: Real-time "agent working" indicator (no extra PR)

Use the HV-047 signal channel + HV-048 board UI:

- When a bot starts work on a ticket, publish a `claim`-type signal with `{ refs: [hvId] }`.
- The board, subscribed to the channel, renders a transient "🤖 nectar working" badge on the ticket card while it's still in `backlog/` (or wherever).
- Badge clears when the underlying ticket actually moves (file system catches up).

Pro: no extra PR ceremony, real-time visibility. Con: requires HV-048 (board UI panel) to land first.

### Decision

I lean **Option A** as the primary fix and **Option B** as a future complement. A is shippable today (just convention update); B requires HV-048 which is currently deferred.

## Desired output
A user opens the board mid-day and immediately sees:

- "nectar is working on HV-052"
- "tern is working on HV-046"

…in the In-Progress column. The swarm becomes visible.

## Success signals
- The In-Progress column has cards in it whenever any bot is working.
- A user can answer "who's doing what?" by looking at the board, no chat needed.

## Failure signals
- Bots skip the claim-PR step (Option A) — visibility regresses.
- Real-time badge gets out of sync with file-system state (Option B).

## Tests
- Manual: a bot starts work; the board shows the ticket in In-Progress within 2 min.
- Manual: bot finishes, ticket moves to in-review; In-Progress column updates.
