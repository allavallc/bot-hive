## Goal
End-to-end verify Bot Hive on the Render prod URL: sign-in, connect a repo, live board updates from a real push, and the multi-account derived-membership flow that HV-019 built.

## Why
Deploy isn't done until the actual user-facing flows work. Doubles as the long-deferred HV-019 acceptance test — the multi-account scenario only really works on a public URL.

## Done when
- A fresh GitHub account can sign in to prod and connect a repo.
- A second GitHub account, added as a collaborator to that repo, sees the project on its dashboard with no manual import (HV-019 derived membership).
- A `hive/` commit pushed to the repo updates both accounts' live boards via SSE within ~10s.
- Removing the second account as a collaborator drops the project from its dashboard within ~5 min (cache TTL).
- HV-019 in `hive/in-review/` gets moved to `hive/done/` with `Verification: human-reviewed`.

## Desired output
The full Bot Hive product loop runs on a public URL. Two accounts, one shared board, live updates. Foundation for any external demo.

## Success signals
- Both accounts see the same tickets, in the same columns, at the same time.
- SSE updates arrive within ~10s of push (Render logs show webhook delivery, broadcast fires).
- No `console.error` in Render logs during the full flow.

## Failure signals
- One account sees the project, the other doesn't → access helper bug or cache desync (rare; HV-018 has tests).
- SSE drops after a few minutes → Render's connection limits; rare.
- 5xx during sign-in → check Render logs, usually env-var typo.

## Tests
- This ticket *is* the test. No new automated coverage.

## How to test
1. Open prod URL in browser A (your main GitHub account). Sign in. Confirm `/dashboard` loads.
2. From browser A, install the GitHub App on a test repo. Confirm it appears on the dashboard.
3. On github.com, add a second GitHub account (or a friend) as a collaborator on that repo.
4. Open prod URL in browser B (different browser or incognito; the second GitHub account). Sign in. Confirm the project auto-appears on browser B's dashboard.
5. From browser B, click into the project. Confirm the board renders with live tickets.
6. With both browsers showing the same board, push a commit that moves a ticket from `hive/backlog/` to `hive/in-progress/`. Confirm both browsers update within ~10s.
7. Remove the second account as a collaborator on github.com. Wait 5 min. Reload browser B's dashboard. Confirm the project is gone.
8. If everything passes, accept HV-019 and mark this one done.

## Notes
- If the multi-account test fails, the bug is most likely in HV-019's wiring (rare) or HV-018's cache (also rare). Reject HV-019 and flag here.
- Out of scope: load testing, broken-state recovery testing, edge cases where collaborators have weird org permissions.
