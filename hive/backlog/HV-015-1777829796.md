## Goal
Plug the Gmail SMTP credentials into `.env` so the `/contact` form actually delivers mail.

## Why
The form code, validation, and nodemailer transport all shipped (HV's `/contact` page + `src/lib/contact-action.ts`). The page renders, the form posts, but the action returns *"Email isn't configured on the server. Please email directly."* until `SMTP_USER` and `SMTP_PASS` are set. This is a one-time manual setup tied to a specific Gmail account, not something a bot can automate.

## Done when
- 2-Step Verification is on for the destination Gmail account.
- A Gmail App Password is generated at https://myaccount.google.com/apppasswords (app: "Mail" or custom name "Bot Hive").
- Local `.env` carries `SMTP_USER`, `SMTP_PASS`, `CONTACT_TO` — all populated.
- **Render env vars** (`SMTP_USER`, `SMTP_PASS`, `CONTACT_TO`) updated from their HV-023 placeholder values to the real Gmail App Password.
- Dev server is restarted so the new env vars load.
- A test submission from `/contact` (local AND prod) arrives in `allavallc@gmail.com`. Hitting **Reply** on the email goes back to the original submitter (Reply-To is set in the action).

## Desired output
The contact form's success state ("Sent. Talk soon.") fires, and an email lands in the inbox within seconds.

## Success signals
- Test submission delivered, Reply-To populated correctly.
- No SMTP errors in dev server logs.

## Failure signals
- 535 auth error from Gmail → wrong password or 2FA not enabled.
- Email lands in spam → likely the From address (which is `SMTP_USER`) is being flagged; reduce by using the same Gmail address as both From and To, or set up a verified sending domain later.
- "Less secure apps" error → must use an App Password, not the account password.

## Tests
- Manual: submit a test entry from `/contact`, confirm delivery + Reply-To.
- Manual: temporarily blank `SMTP_PASS`, submit, confirm the user-facing "Email isn't configured" error appears (no crash).

## How to test
1. Enable 2-Step Verification on the Gmail account if not already on: https://myaccount.google.com/security
2. Generate an App Password: https://myaccount.google.com/apppasswords
   - **App**: pick "Mail" or "Other (Custom name)" → "Bot Hive"
   - Google shows a 16-character password formatted as four 4-char groups (e.g. `abcd efgh ijkl mnop`). Copy it. **Strip the spaces** when pasting into `.env`.
3. Edit `.env` (project root) and set:
   ```
   SMTP_USER=allavallc@gmail.com
   SMTP_PASS=<the-16-char-password-no-spaces>
   CONTACT_TO=allavallc@gmail.com
   ```
   `SMTP_USER` and `CONTACT_TO` can be the same address — Gmail SMTP requires `From` to match the authenticated user, and we want messages to land in the same inbox.
4. Restart dev: kill the running `npm run dev` (Ctrl+C in its terminal), then `npm run dev` again. Env vars only load at startup.
5. Visit `http://localhost:3000/contact`, fill out the form with a real test email in the From field, submit.
6. Check `allavallc@gmail.com` — message should arrive within a few seconds. Subject is `Bot Hive contact form — <Name>`. Hit **Reply** in Gmail and confirm it addresses to the email you put in the form (not to yourself).
7. **Update Render**: in the bot-hive Web Service → Environment, replace the dummy `SMTP_USER`, `SMTP_PASS`, `CONTACT_TO` values with the real ones from step 3. Save → triggers redeploy.
8. Once Render is back Live, repeat step 5–6 against the prod URL.

## Notes
- App Passwords are 16 chars and only show once. If lost, generate a new one.
- App Passwords work even when 2FA is on — that's the point. Regular passwords don't work with 2FA-enabled accounts via SMTP.
- For production deploy later, this same flow works on Render (paste the values into Render's env vars). The code reads `process.env.SMTP_USER` / `SMTP_PASS` regardless of host.
- If we hit Gmail's send limits (~500/day for personal accounts) or want a dedicated sending domain, swap to Resend / SendGrid — only the transporter config changes, the action signature stays the same.
- Out of scope: rate-limiting the form (spam defense), CAPTCHA, queueing failed sends.
