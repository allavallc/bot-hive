## What

Fix the current regression where requesting the colony snapshot endpoint with a project repo query returns HTTP 500 instead of a stable colony payload.

Observed repro from shell:

1. `curl -i -sS 'https://bot-hive-j0ax.onrender.com/api/bots/colony?repo_full_name=allavallc/bot-hive'`
2. Current result: `HTTP/2 500`
3. Expected result: `200` with `{ "colonies": [...] }` or an intentional auth/validation status if the endpoint contract changed

The goal is to identify whether the failure is in project lookup, auth/session handling, colony query logic, or an unhandled null/exception path, then restore a reliable endpoint contract.

## Why

`/api/bots/colony` is the current shared source of truth for bot-seat / colony visibility. If it 500s, every surface layered on top of it becomes suspect:

- My Bot Team modal state
- seat-strip / board visibility
- startup-state verification during HV-136 follow-up

Without a trustworthy colony endpoint, we cannot distinguish UI rendering bugs from backend state regressions.

## Done when

- [ ] Repro is captured from current code/runtime with the failing path identified
- [ ] `GET /api/bots/colony?repo_full_name=allavallc/bot-hive` no longer returns 500 for the normal project case
- [ ] The endpoint returns a deliberate, documented non-500 status for any remaining invalid-input or auth edge cases
- [ ] Active-bot surfaces that depend on the endpoint can fetch colony state without crashing on this path
- [ ] Add or update a targeted test for the regression path if coverage is nearby

## Desired output

A coder bot should land:

- the endpoint fix
- a regression test where practical
- a short note in the ticket/PR naming the actual failing layer

## How to test

1. Re-run `curl -i -sS 'https://bot-hive-j0ax.onrender.com/api/bots/colony?repo_full_name=allavallc/bot-hive'`.
2. Verify the response is no longer 500.
3. Verify the board/modal surface that reads colony state can load without this backend failure.
4. If auth is required by design, verify the endpoint now returns the intended explicit status instead of 500.

## Notes

- Prefer fixing the underlying endpoint contract over adding UI-side fallback heuristics.
- Keep this scoped to the colony snapshot regression, not broader bot-team UX redesign.
