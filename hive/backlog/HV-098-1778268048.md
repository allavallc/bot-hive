## Goal
Server-side validation in the reject endpoint enforces that rejection reasons from the tester role are ≤ 280 chars (~2 sentences). Reject with 400 if exceeded. Forces the tester to be specific instead of producing bullet-list nitpicks.

## Done when
- Reject endpoint inspects the actor — if the actor is a tester (per FS Role field), apply the 280-char cap; otherwise allow the existing length (humans can be verbose)
- Validation error returns 400 with a clear message; the tester bot retries with a shorter reason
- Tester rubric (HV-095) calls out the cap as a hard rule

## Notes
- Cap only applies to tester rejections, not human rejections — humans get full flexibility on reject reasons.
- 280 chars is the same cap we use for notes-to-bots; consistent with the platform's "short, specific" pattern.
