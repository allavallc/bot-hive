## Goal

Land the DB substrate plus the two read/create endpoints that every other ticket in FS-028 depends on. Nothing else in the FS can start until this is in.

## Concrete changes

- **Alembic migration** — new `bots` table per the spec schema. Includes the partial unique index `bots_active_seat_uniq ON bots (colony, seat) WHERE status = 'active'`.
- **Model** — SQLAlchemy model matching the schema. `status` enum: `('active', 'offline')`.
- **`POST /api/bots/join`** — allocate the lowest free seat in `1..N+1` for the colony. Use `SELECT … FOR UPDATE` on a per-colony lock row to serialize. If `(colony, handle)` exists with `status='offline'`, reactivate it with a new lowest-free seat and refresh `last_heartbeat_at`. Return `{seat, total, role, skill_files}`. Role is derived from seat via `hive/roles.md` (server reads that file once at startup or per-request — see Notes).
- **`GET /api/bots/whoami?colony=X&handle=Y`** — return the same shape as `/join` from DB state. 404 if no active row for that pair.
- **Per-colony lock row** — either a separate `colony_locks` row or use advisory locks (`pg_advisory_xact_lock(hashtext(colony))`). Pick advisory locks (simpler, no extra table). Document the choice.

## Notes

**Role derivation source.** The seat → role mapping is in `hive/roles.md` today. Options: (a) parse the markdown table at server startup and cache, (b) hardcode the table in Python, (c) ship the mapping as a JSON sibling file. Recommend (a) — single source of truth; the markdown stays authoritative for humans, server parses on boot. (b) is fastest but creates drift risk; (c) duplicates data. Document the parse step.

**Why advisory locks over a `colony_locks` table.** Advisory locks are session-scoped, automatically released on transaction end, and require no schema. The lock contention path is short (insert + maybe one update), so the lock window is sub-millisecond per request. A `colony_locks` table is fine too but adds a migration and a row per colony for nothing.

**Skill-files response field.** Returned as an array of paths relative to the repo root (`["hive/skills/coder.md"]`). The bot is responsible for reading those files from its checkout — the server doesn't return file contents.
