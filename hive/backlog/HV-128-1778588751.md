## Goal

The walking creature on a card's perimeter represents the actor who needs to act NEXT, not a fixed bot icon. Display rule by state:

- **`in-progress`** → bot icon (the coder is working).
- **`in-review` AND next actor is a bot tester** (`User-facing: no` AND a tester bot is active in the colony) → bot icon, tester variant if distinguishable.
- **`in-review` AND next actor is the operator** (`User-facing: yes`, OR `User-facing: no` with no active tester bot in the colony) → human icon walking.
- **`done`** → no walker.
- **`blocked` / `not-doing`** → no walker.

The "next actor is a bot tester" branch must consider whether the colony actually has a tester. A 1-bot colony with `User-facing: no` still routes to the operator, because the consolidated bot cannot review its peer's work in isolation (and the operator is the ultimate fallback).

## Concrete changes

- **`src/app/projects/[id]/board.client.tsx`** (or wherever the perimeter walker is rendered — likely a sibling of the handle badge changed in HV-127) — replace the hardcoded bot icon with a `walkerIcon(ticket, colonyState)` helper that picks bot vs human per the rule above.
- **Human icon asset** — pick or add an SVG/emoji that pairs visually with the existing bot walker (same size, same motion path, same speed).
- **Colony state input** — the helper needs to know whether a tester bot is active. Reuse whatever HV-127 / FS-027 already computes for `currentActor(ticket)` so the two stay consistent.
