## What

Rewrite `scripts/stream.ps1` and `scripts/stream.sh` so they:

1. Accept a request-scoped startup id (`-StartupId` / `--startup-id`).
2. No longer require `.bot-hive-identity` before connecting.
3. If `.bot-hive-identity` contains a handle, include that handle in the stream URL so the server binds the pre-created worktree identity.
4. On `your-role` event: extract the server-assigned `handle`, write `.bot-hive-identity`, write `.bot-hive-role-notice`.
5. If another live stream already owns cwd, create/use `worktrees/<handle>/` for this bot and write state there.
6. Write `.bot-hive-startups/<startup-id>.json` so the foreground agent knows which worktree/session root belongs to this startup.

No shared `.bot-hive-role-ptr`; simultaneous Bot 2 / Bot 3 startups must not race.

## Multi-bot isolation

When a bot starts at the repo root and another bot's `.bot-hive-stream.pid` is already alive there:

1. Detect the existing live PID.
2. Continue only if the startup passed a startup id.
3. Connect to the server and receive/bind a handle.
4. Create/use `worktrees/<handle>/`.
5. Write `.bot-hive-stream.pid`, `.bot-hive-identity`, `.bot-hive-role-notice` to that worktree.
6. Write `.bot-hive-startups/<startup-id>.json` at the original cwd with `stateDir`, `noticePath`, `handle`, `role`, `seat`, `total`, and `skillFiles`.

For the primary bot (no existing live PID at cwd): write files to cwd as before and still write the startup handoff when a startup id is provided.

## `bot-startup.md` change

Step 2 waits for `.bot-hive-startups/<startup-id>.json` first. If it points at a worktree, the agent treats that worktree as its session root for all future commands. Legacy fallback may read `.bot-hive-role-notice` directly when no handoff exists.

## Done when

- Bot starting at root with no live PID: stream writes identity + role notice at root and startup announces correctly.
- Bot starting at root while another bot is live: stream creates/uses `worktrees/<handle>/`, writes request-scoped handoff, and startup announces the correct bot without reading another bot's files.
- Bot 2 and Bot 3 starting close together use different startup ids and cannot consume each other's handoff.
- `.bot-hive-identity` is not required for solo/root startup, but when Add-a-Bot prewrites it the stream binds that handle.
- `stream.ps1` and `stream.sh` both implement matching behavior.

## Implementation notes

- `colony` from `gh api user --jq .login`, with `.bot-hive-identity` as a local fallback for spawned/background shells.
- `your-role` event JSON includes `handle`, `role`, `seat`, `total`, and `skillFiles`.
- PID detection: POSIX `[ -f .bot-hive-stream.pid ] && kill -0 "$(cat .bot-hive-stream.pid)" 2>/dev/null`; PowerShell `Test-Path + Get-Process` pattern already in hive.ps1.
- On reconnect: bind the same handle from `.bot-hive-identity` / current stream state. If the server returns a different handle for an established stream, exit rather than mixing bot state.
