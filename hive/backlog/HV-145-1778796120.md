## What

Rewrite `scripts/stream.ps1` and `scripts/stream.sh` so they:

1. No longer require `.bot-hive-identity` before connecting.
2. Connect with `colony` only (no `handle` in the URL).
3. On `your-role` event: extract the server-assigned `handle`, write `.bot-hive-identity`, write `.bot-hive-role-notice`.
4. Handle multi-bot isolation automatically (secondary bots create their own worktree).

Also update `hive/bot-startup.md` step 2 to document the `.bot-hive-role-ptr` fallback.

## Multi-bot isolation

When a bot starts at the repo root and another bot's `.bot-hive-stream.pid` is already alive there, the stream script must not overwrite the existing bot's state files. Instead:

1. Detect existing live PID at cwd before connecting.
2. Connect to server, receive handle.
3. `git worktree add worktrees/<handle> -b <handle>-work main` (skip if already exists).
4. Write `.bot-hive-stream.pid`, `.bot-hive-identity`, `.bot-hive-role-notice` to `worktrees/<handle>/`.
5. Write `.bot-hive-role-ptr` to cwd containing `worktrees/<handle>` — this is the pointer the startup procedure polls for.
6. On subsequent `your-role` events (role changes): write notice to `worktrees/<handle>/`.

For the primary bot (no existing live PID at cwd): write all files to cwd as before.

## `bot-startup.md` change

Step 2 ("Wait for the role notice") gains a fallback:

> Poll for `.bot-hive-role-notice` OR `.bot-hive-role-ptr` at cwd (max 30s).  
> If `.bot-hive-role-ptr` appears first: read the path from it, then poll for `.bot-hive-role-notice` at that path.

## Done when

- Bot starting at root (primary): stream writes identity + role notice at root. Startup announces correctly.
- Bot starting at root (secondary, another bot already running): stream creates `worktrees/<handle>/`, writes ptr at root, writes files in worktree. Startup reads ptr, finds notice, announces correctly.
- `.bot-hive-identity` is no longer required to exist before startup (stream creates it).
- `stream.ps1` and `stream.sh` both implement identical behavior.

## Implementation notes

- `colony` from `gh api user --jq .login` (POSIX) or `gh api user | ConvertFrom-Json | Select-Object -ExpandProperty login` (PowerShell) — same pattern already used elsewhere.
- `your-role` event JSON now includes `handle` field (added by HV-144). Parse it alongside `role`, `seat`, `total`, `skillFiles`.
- PID detection: POSIX `[ -f .bot-hive-stream.pid ] && kill -0 "$(cat .bot-hive-stream.pid)" 2>/dev/null`; PowerShell `Test-Path + Get-Process` pattern already in hive.ps1.
- On reconnect (inner loop exits → retry): if secondary bot, re-write notice to `worktrees/<handle>/`; don't re-create worktree or re-write ptr.
