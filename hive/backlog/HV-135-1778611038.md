## Goal

Wire `scripts/check-role` into Claude Code's `UserPromptSubmit` hook so role changes are detected and announced at the start of every agent turn, with no operator action required. Document the equivalent wiring for the other supported agent hosts.

## Concrete changes

- **`.claude/settings.json`** — add a `UserPromptSubmit` hook entry that runs `scripts/check-role.sh` (POSIX) or `scripts/check-role.ps1` (Windows). The hook injects the script's stdout into the user prompt context. Use the host's documented hook format (Claude Code's `hooks` array).
- **`hive/seats.md`** — extend the "hook setup" section (created in HV-134) with per-agent instructions:
  - **Claude Code**: copy the `.claude/settings.json` snippet shipped in this PR.
  - **Codex**: equivalent hook config (Codex's pre-prompt hook syntax).
  - **Cursor / Aider / Gemini**: each has its own pre-prompt mechanism. Document the one-line wiring or, if a host has no equivalent, note that the bot falls back to script-invocation-time detection (still correct, just less immediate).
- **Optional `scripts/install-hook.{sh,ps1}`** — tiny helper to write the right hook config for the detected host. Only ships if per-agent wiring is fiddly enough to warrant automation. Default: just document.

## Notes

**Why `UserPromptSubmit` over `SessionStart`.** `SessionStart` fires once per session; `UserPromptSubmit` fires every turn. The whole point is to catch role shifts that happen *during* a session.

**Per-agent surface.** Different agent hosts have different hook lifecycles. The contract is one-line simple: "run `scripts/check-role.{sh,ps1}` before every user prompt; any stdout is treated as a system note appended to the prompt context." Hosts that can't honor that exact contract fall back to script-time detection (HV-133 builds this into `my-work.sh` and `claim.sh`).

**Hook performance.** `check-role` is a single HTTP GET. Should resolve in 50–200ms locally, longer on cold Render. If hook latency becomes a UX issue, cache the role on the client for N seconds and only call the server every N seconds; defer until we see the problem.

**Operator's main checkout (no bot identity).** Hooks fire there too. `check-role` exits cleanly with no output when `.bot-hive-identity` is absent, so the operator's session is unaffected. Verify this explicitly in Done-when.

**Out of scope:**
- Pre-tool / post-tool hooks. We only need pre-prompt for this feature.
- Auto-detect of which agent host is running (just document and let the operator copy the right snippet).
