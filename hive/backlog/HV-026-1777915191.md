## Goal
Wire Sentry into the prod Bot Hive build so unhandled errors and 5xx responses surface in a dashboard rather than vanishing into Render's log tail.

## Why
Once the app has any users, silent errors become invisible bugs. Sentry's free tier is enough for this scale. Setting it up *after* the smoke test passes (HV-025) keeps the deploy work simple — fewer moving parts during the first deploy.

## Done when
- `@sentry/nextjs` installed and configured per its setup wizard.
- `sentry.client.config.ts` and `sentry.server.config.ts` created with sensible defaults (sample rate 1.0 for now; reduce later when traffic warrants).
- `SENTRY_DSN` env var set in Render (and locally if we want dev errors captured — probably not for noise reasons).
- Source maps uploaded to Sentry as part of the build (Sentry's Next.js plugin handles this).
- A deliberately-thrown test error from a route shows up in the Sentry dashboard within a minute.

## Desired output
When something breaks on prod, the error appears in Sentry with a stack trace and a link back to the file/line. No more grepping Render logs after the fact.

## Success signals
- Test error appears in Sentry within ~60s.
- Sentry's source-map mapping works (file paths in stack traces match the source).
- No new errors flagged for normal flows (sign-in, dashboard, board, push → SSE update).

## Failure signals
- Source maps don't upload → check the Sentry plugin config.
- Sentry quota maxed by something noisy → reduce sample rate or filter at source.
- Local dev gets noisy if `SENTRY_DSN` is set locally — keep it unset locally unless we want it.

## Tests
- Manual: throw a test error from a server action or route; confirm it appears in Sentry.

## How to test
1. After deploying with Sentry configured, create a temporary route or server action that throws (`throw new Error("HV-026 sentry test")`).
2. Hit it from the prod URL.
3. Within a minute, check the Sentry dashboard. Confirm the error appears with a working stack trace.
4. Remove the temporary route. Push. Confirm the error stops repeating.

## Notes
- Sentry free tier: 5k errors/mo, 10k performance units, 50 replays. More than enough for early Bot Hive.
- Out of scope: alerting rules, Slack integration, performance monitoring (defer until traffic justifies it).
- The Next.js Sentry plugin auto-instruments most things; manual `Sentry.captureException` calls only needed for caught-but-still-bad errors.
