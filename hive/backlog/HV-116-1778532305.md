## Goal

Add-a-Bot supports two modes:

1. **Existing mode (worktree-spawned bot)** — current default. Creates `worktrees/<handle>/`, writes identity there, opens a new terminal in that dir. For bots 2, 3, etc.
2. **New mode (first bot in main checkout)** — checkbox/toggle "This is my first bot — set up identity in this checkout." Step 1 writes `.bot-hive-identity` to the current working directory (the main checkout), no worktree, no new terminal. The session the human is already running becomes the bot.

Result: any human starting a fresh colony bootstraps cleanly via the same UI affordance, never touching identity files manually.

## Concrete changes

- **`src/app/projects/[id]/add-bot-button.client.tsx`** — modal gains a "first bot in current checkout" toggle. When checked, `step1Command()` returns a script that writes identity to `.bot-hive-identity` in CWD instead of `worktrees/<handle>/.bot-hive-identity`, and skips the `git worktree add` + `wt.exe new-tab` calls.
- **`src/app/api/projects/[id]/next-handle/route.ts`** — accept a `firstBot=true` query param to flag this mode in the response (so the UI shows different copy).
- **`hive/HIVE.md`** — document the bootstrap path: "for the first bot in your colony, use 'first bot' mode in Add-a-Bot."
