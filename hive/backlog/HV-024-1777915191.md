## Goal
Add the Render prod URLs to the GitHub OAuth App's authorised callback list and to the GitHub App's webhook + Setup URLs, alongside the existing `localhost:3000` entries (don't replace — local dev keeps working).

## Why
After HV-023 the app is reachable at a public URL but GitHub still bounces every OAuth callback to localhost and still posts every webhook to the smee proxy. Until these URLs are updated, prod is effectively unreachable.

## Done when
- GitHub OAuth App (github.com → Settings → Developer settings → OAuth Apps → Bot Hive):
  - Authorisation callback URL list now contains both `http://localhost:3000/api/auth/callback/github` AND `https://<render-prod-url>/api/auth/callback/github`.
- GitHub App (github.com → Settings → Developer settings → GitHub Apps → Bot Hive):
  - **Webhook URL** set to `https://<render-prod-url>/api/github/webhook`. (No more smee in prod; smee stays for local dev.)
  - **Setup URL** set to `https://<render-prod-url>/projects/install/callback`.
  - **Callback URL** set to `https://<render-prod-url>/projects/install/callback` (same path).
  - Local dev still works because the App's "Redirect on update" toggle is off and we use the GitHub OAuth App for sign-in, not the App.
- A test push to a connected repo fires the webhook to the prod URL (verify in Render logs).

## Desired output
Sign-in from the prod URL completes the OAuth round-trip. Pushes to a connected repo update the live board on prod.

## Success signals
- Render logs show `POST /api/github/webhook` requests when commits are pushed.
- A sign-in attempt from the prod URL redirects to GitHub, then back to `https://<render>/dashboard`.
- Local dev still works (callback to `localhost:3000` continues to function).

## Failure signals
- `redirect_uri_mismatch` from GitHub on sign-in → callback URL not whitelisted; fix the OAuth App settings.
- Webhook 401s in prod → `GITHUB_APP_WEBHOOK_SECRET` mismatch between Render env and the GitHub App settings.

## Tests
- Manual: sign in from the prod URL, confirm callback succeeds, dashboard loads.
- Manual: push to a connected repo, confirm webhook hits prod and the board updates.
- Manual: sign in from `localhost:3000` (local dev), confirm still works.

## How to test
1. Visit the Render prod URL → click Sign in with GitHub. Expected: redirect to GitHub, authorise, redirect back to `/dashboard`.
2. Push a `hive/` commit to a connected repo. Watch the Render logs — expect `POST /api/github/webhook 200`. Reload `/projects/[id]` in prod, see the board reflect the change.
3. Run `npm run dev` locally, open `localhost:3000`, sign in. Expected: still works (callback URL list has both entries).

## Notes
- The webhook secret is the same across dev and prod — both env files point at the same `GITHUB_APP_WEBHOOK_SECRET`. Smee just forwards; prod hits directly.
- If for some reason we want different webhook secrets in dev vs prod, we'd need separate GitHub Apps — out of scope here.
- Out of scope: custom domain (would mean a second URL to add, but adding another callback later is just another github.com edit).
