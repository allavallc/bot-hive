## Goal

Include relevant ticket, feature-set, and curated learning context when the server routes work to a bot.

## Why

Agents should not start from a bare ticket ID. The server can improve predictability by packaging the feature goal, related blockers, previous rejection patterns, and durable local learnings into the event that triggers work.

## Done when

- Handoff/review events include a compact context object with ticket ID, feature set, current state, and related IDs.
- Curated learnings can be included as plain text snippets without requiring users to install Hindsight.
- Context injection is additive and does not override current ticket acceptance criteria or role rubrics.
- Oversized context is capped or summarized before delivery.

## Desired output

Bots receive enough context to begin work or review without rediscovering known constraints.

## Success signals

- Repeated failures become checklist/context snippets rather than tribal knowledge.
- Bot handoffs require fewer human clarifications.

## Failure signals

- Context payloads become too large for terminal agents to use.
- Injected learnings conflict with the ticket or role rubric.

## Tests

- Unit tests for context builder limits and included fields.
- Manual test that a ready-for-review event includes ticket and feature-set context.

## How to test

- Trigger a handoff for a ticket with a feature set and related blocker, then inspect the SSE payload.

## Notes

Hindsight remains a project-owner curation source for now, not a production dependency for users.
