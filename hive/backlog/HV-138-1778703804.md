- **Verification**:
- **Failure mode**: Operators running 2–3 bots side-by-side in VS Code's integrated terminal currently see all tabs labeled `claude` / `powershell` / `bash` — indistinguishable. Once a colony has wren (PM), buzz (coder), and falcon (tester), the operator can't tell which tab is which bot, and when roles consolidate/split on join/leave, there's no visual cue. HV-104 set the title at spawn time but didn't track role changes, so a bot whose role shifted from `PM + coder + tester` to `PM + tester` keeps its stale label.

## Goal

Each bot's terminal tab shows `<Handle> (<Role>)` in VS Code (and any other terminal emulator that honors OSC title escapes). The label updates automatically whenever the server pushes a role change down the SSE stream.

Examples:
- Solo colony: `Wren (PM + coder + tester)`
- After coder joins: `Wren (PM + tester)`, `Buzz (coder)`
- After tester joins: `Wren (PM)`, `Buzz (coder)`, `Falcon (tester)`
- After coder shuts down: `Wren (PM + coder + tester)` if alone, or `Wren (PM + tester)` + `Falcon (coder)` (server-derived).

## Concrete changes

### Bootstrap (initial title)

In `hive/bot-startup.md` Procedure A step 4 and Procedure B step B.4 — right after the bot reads its role and announces — set the terminal title. Per platform:

- POSIX (bash): `printf '\033]0;<handle> (<role>)\007' > /dev/tty`
- Windows (PowerShell): `$Host.UI.RawUI.WindowTitle = "<handle> (<role>)"` (this calls `SetConsoleTitle`, which VS Code's ConPTY translates to OSC for the tab renderer)

The implementation should add a small helper, e.g. `scripts/set-title.{sh,ps1}` (or inline in the bootstrap doc), invoked once at bootstrap with the current `<handle>` and `<role>`.

### Role-change auto-update

`scripts/check-role.{sh,ps1}` is the UserPromptSubmit hook that already reads `.bot-hive-role-notice` on every operator prompt to surface `[BOT-HIVE] Role changed: …`. Extend it: after parsing the notice, also set the terminal title to `<handle> (<role>)` using the same helper.

Because the hook runs on every prompt, the title stays in sync with the role even if the operator doesn't restart the agent.

### Shutdown

`hive/bot-shutdown.md` step 3 currently prints the all-clear line. Before that, reset the terminal title to a neutral value (e.g., `claude` or the operator's shell default) so a closed/dead tab doesn't keep showing a stale bot name. Implementation: same helper, called with no args clears to `""`, which most terminal emulators fall back to a sensible default for.

`scripts/hive.{sh,ps1} stop` (the operator-side stop CLI) should do the same.

## Done when

- `scripts/set-title.{sh,ps1}` exists (or an inline equivalent documented in `hive/bot-startup.md`). Accepts a single arg, the title string. On POSIX writes the OSC sequence to `/dev/tty`; on Windows sets `$Host.UI.RawUI.WindowTitle`.
- `hive/bot-startup.md` Procedure A step 4 and Procedure B step B.4 call the helper after announce.
- `scripts/check-role.{sh,ps1}` calls the helper at the end of every invocation so the title stays in sync with `.bot-hive-role-notice`.
- `hive/bot-shutdown.md` step 3 and `scripts/hive.{sh,ps1} stop` reset the title before printing the all-clear.
- Manual confirmation in VS Code: opening three tabs (`start the hive` → `hive add coder` → `hive add tester`) shows three distinct title strings; the wren tab's title visibly changes when buzz joins and again when falcon joins.

## Success signals

- VS Code tab list looks like `Wren (PM)` / `Buzz (coder)` / `Falcon (tester)` instead of three `claude` tabs.
- Role change message and title change happen on the same operator prompt — no lag.
- Works in PowerShell, git-bash, WSL (Linux terminals).
- Works in plain Windows Terminal (non-VS-Code) too — same OSC mechanism.

## Failure signals

- Hook subprocess can't reach the parent terminal's ConPTY → title doesn't update. (Caveat below.)
- OSC escape gets captured by Claude Code's hook output handling instead of being emitted to the terminal. (Caveat below.)
- Title gets set but never cleared — stale `Wren (PM)` lingers after the bot has signed off.
- Multiple agents fight over the same tab's title (only one process owns the tab; should be a non-issue per worktree because each tab has its own claude session).

## Tests

- Unit: helper script parses input, emits the right escape sequence on POSIX, sets `WindowTitle` on Windows.
- Manual end-to-end (3-bot): solo → add coder → add tester → sign off coder → sign off tester. Verify the wren title transitions through every consolidation state.
- Manual cross-platform: VS Code on Windows (ConPTY), VS Code on Mac (WSL/Mac shell), plain Windows Terminal, gnome-terminal — at least one each to confirm OSC reach.

## Notes

**Caveat to verify during implementation:** hook subprocesses inherit the parent's console handles on Windows, so `$Host.UI.RawUI.WindowTitle` SHOULD propagate to the VS Code tab. If it doesn't (e.g., because Claude Code spawns hooks with a detached console), fallback options:

1. Have the agent itself emit the OSC escape at the start of its response when it detects a role change — the agent's stdout reaches the terminal. Less precise but reliable.
2. Use the `statusLine` field in `~/.claude/settings.json` (Claude Code's own bottom-of-window status line) instead. Different visual location (inside Claude's UI, not the VS Code tab), but always updateable.

Decide between fallbacks during implementation if the primary mechanism fails.

**Out of scope:** terminal title for non-VS-Code, non-Windows-Terminal terminals (e.g., legacy cmd, niche emulators). Best-effort if the OSC reaches them; explicit support not required.
