## Goal

Inbox button count reflects state immediately after a resolve action.

## Why

Two refresh paths today:

1. `useEffect` interval in `AdminInbox` polls every 30s.
2. Manual refresh on modal open.

Neither fires when the user takes a resolve action inside the modal. The child components (`SuggestionsInbox`, `SwarmHealthPanel`) re-fetch their own state; the parent count doesn't observe.

## Concrete fix paths (pick one)

- **Cheapest:** pass an `onChange` callback from `AdminInbox` down to the children; each calls it after a successful Approve/Reject/Mark-resolved; parent re-runs `refreshCounts()`.
- **More durable:** subscribe `AdminInbox` to the existing `project-changed` SSE event. The PATCH endpoints already broadcast it (per FS-025 docs). Listening client-side closes this and any future similar bugs in one shot.

Recommend the SSE path — it scales to other panels and matches the platform-as-comm-channel design (per `feedback_platform_for_comm_github_for_code.md`).

## Done when

- [ ] No regression: 30s interval refresh still works for state changes that happen outside the modal (e.g. another bot files a suggestion)
