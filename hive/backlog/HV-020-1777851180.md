## Goal
Let any collaborator on a connected repo claim or transfer the billing seat (`billingOwnerId`) for that project.

## Why
Default seat = installer (always a GitHub admin). In corporate settings the dev who installs isn't always the budget holder. Transfer also handles orphan cases: original installer leaves the GitHub repo, another collaborator takes over the seat before billing breaks.

## Done when
- `POST /api/projects/[id]/billing-owner` accepts `{ userId: string }` (claim/transfer). The `billing_owner_id` column is NOT NULL — every transfer must name a successor; release-without-target is disallowed.
- Endpoint validates: requester has GitHub access; target user has GitHub access; both exist in `user`.
- Update wrapped in a transaction.
- Project page shows current billing owner (name + avatar). Non-owners see "Take over billing"; owner sees a dropdown of repo collaborators + "Transfer to…".
- Confirmation modal before transfer or take-over.
- New helper `listRepoCollaborators(githubRepo, installId)` in `src/lib/access.ts`: calls `octokit.repos.listCollaborators` via the App's installation token, cached 5 min.
- Audit: `console.log` the transfer for now (formal audit log → FST-005 or its own polish ticket).

## Desired output
On the project page, any collaborator can claim or transfer the billing seat in two clicks.

## Success signals
- Transfer is atomic.
- New billing-seat label visible to all viewers on next render or SSE tick.
- Audit line in server console: old owner, new owner, requester, timestamp.

## Failure signals
- Race: two simultaneous claims. Last write wins; log both attempts.
- Target user lost GitHub access between dropdown render and submit. Endpoint validates, rejects with a clean error.

## Tests
- Vitest: claim by current collaborator → 200, DB updated.
- Vitest: claim by non-collaborator → 403.
- Vitest: transfer to non-collaborator → 400.
- Vitest: transfer to non-existent user → 404.
- Manual: take over from a second account; original owner's view updates.

## How to test
1. As installer, on the project page note "you are the billing owner".
2. Sign out, sign in as second collaborator. Click "Take over billing"; confirm.
3. Verify page updates: account 2 is now the billing owner.
4. Sign back in as installer. Their view shows account 2 as the new owner.
5. As account 2, click "Transfer to…", pick another collaborator, confirm. Verify the change.

## Notes
- Out of scope: lock-when-unpaid, plan checking, payment flows — all FST-005.
- Collaborator dropdown queries via the App's installation token (canonical collaborator list, not just one user's view).
- `billing_owner_id` is NOT NULL — every project always has a billing owner. Releasing without a target isn't allowed; you must always name a successor when transferring.
