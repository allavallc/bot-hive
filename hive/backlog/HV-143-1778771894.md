## Goal
When a bot receives a `your-role` event triggered by a peer leaving, it speaks unprompted: names who left, states its new role, and confirms which skill files it loaded.

## Why
Currently the role-change is passive — the human has to prompt the bot to find out. A proactive announcement gives the operator confidence that the bot understood the change and is acting on it.

## Desired output (examples)
Bot 2 (role unchanged): "I see that `<handle>` left. I'll continue as coder."
Bot 1 (role expanded): "I see that `<handle>` left. Taking over as tester in addition to PM. Loading `hive/skills/tester.md`."

## Changes
- `check-role.ps1` / `check-role.sh`: when a role-change notice is detected, output a structured block that triggers Claude to speak (not just update the prompt prefix)
- Bot-startup.md / AGENTS.md: instruct bots to respond to role-change notices with a proactive announcement naming the departed bot and new skills

## Done when
- Bot outputs an unprompted message within ~20s of a peer shutting down
- Message names the departed handle (from HV-142's `departed` field)
- Message lists new skill files being loaded
- Human does not need to prompt to see the announcement
