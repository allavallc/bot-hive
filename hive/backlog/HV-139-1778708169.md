- **Verification**:
- **Failure mode**: Bot Hive's bootstrap relies on the agent reading `hive/bot-startup.md` before processing the operator's first prompt. Observed failure: a fresh Claude Code session in Terminal B treated `hive add coder` as a literal shell command instead of recognizing it as a kickoff trigger, because the agent never read the procedures. The Claude Code fix is a `SessionStart` hook in `.claude/settings.json` that runs `scripts/inject-bot-startup.sh` and pipes `bot-startup.md` into the agent's initial context. That fix is Claude-specific. Codex / Cursor / Aider / Gemini / etc. each need their own equivalent or they will hit the same bug.
- **User-facing**: yes (operator-facing: bots silently fail to bootstrap on non-Claude agents)

## Goal

Every supported agent (not just Claude Code) gets `hive/bot-startup.md` injected into its initial context automatically, via whatever per-agent mechanism that platform exposes. Single source of truth stays in `hive/bot-startup.md`; per-agent configs just point at it.

## Concrete changes

Per agent, identify the equivalent of Claude Code's `SessionStart` hook and wire it up:

| Agent | Likely config location | Mechanism to investigate |
|---|---|---|
| **Codex CLI** | `~/.codex/config.toml` or `.codex/` | Codex has hooks; confirm the exact event name and JSON schema |
| **Cursor** | `.cursor/rules/` | Cursor reads rule files; may or may not have a true session-start hook. If not, fall back to a rule file that explicitly tells the agent to read bot-startup.md before first action |
| **Aider** | `.aider.conf.yml` or `.aider/` | Aider has `read` config field that auto-injects files; may work directly |
| **Gemini CLI** | `GEMINI.md` or its skills system | Gemini has skill activation; investigate whether session-start auto-activation is supported |

For each agent:

1. Verify the agent honors the chosen mechanism (run a fresh session, type a kickoff phrase, confirm the agent recognizes it instead of treating it as a shell command).
2. Wire the config into the repo at the agent-specific path so it ships with the project.
3. Document the per-agent setup in `AGENTS.md` under a new "Per-agent bootstrap injection" section.

If an agent has NO session-start mechanism, fall back to: tell the operator to manually type "read hive/bot-startup.md and stand by" as their first prompt. Mark that agent as best-effort in the docs.

## Done when

- At least Codex CLI and Aider have working SessionStart-equivalent injection. (Cursor and Gemini are stretch goals if their platforms support it.)
- `AGENTS.md` documents the per-agent setup, one short subsection per supported agent.
- Manual test: fresh session in each supported agent, type `hive add coder`, agent recognizes the kickoff trigger and runs Procedure B (not a shell command).
- The Claude Code injection (already shipped) is unchanged.

## Success signals

- Adding bot-startup.md content as the first context is reliable per-agent (operator never has to manually paste docs).
- A new contributor on Codex / Aider can spawn bots the same way a Claude Code operator does, with no extra setup beyond their normal agent install.

## Failure signals

- Per-agent config drifts from Claude Code's; agents disagree about kickoff triggers.
- An agent has no session-start mechanism AND no way to register a rule that fires before first user input — that agent is unusable for bot-hive without operator hand-holding.

## Tests

- Manual end-to-end per agent: launch fresh terminal, run agent, type `hive add coder`. Confirm agent reads bot-startup.md, runs Procedure B, spawns the coder, transforms itself, announces.
- Manual end-to-end: type `start the hive` in a clean checkout. Agent must run Procedure A (with preflight) and become the PM.
- Negative test: ensure that if the per-agent hook fails to fire, the agent falls back gracefully (or surfaces a clear error) rather than executing kickoff phrases as shell commands.

## Notes

The Claude Code mechanism we shipped is `.claude/settings.json` → `SessionStart` → runs `scripts/inject-bot-startup.sh` which `cat`s `hive/bot-startup.md`. That's the reference implementation; the per-agent equivalents should produce the same effect: the entire content of bot-startup.md visible in the agent's context before the operator's first prompt is processed.

If a platform has no real session-start mechanism, the next-best fallback is a "you-must-read-this-first" rule file the agent loads at activation. Cursor's `.cursor/rules/` works this way.
