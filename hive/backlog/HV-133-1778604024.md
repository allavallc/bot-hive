## Goal

Replace the event-log-scanning `whoami` with a server call and ship the two new scripts the boot/hook lifecycle needs (`check-role` for in-session role-change detection, `heartbeat` for liveness).

## Concrete changes

- **`scripts/whoami.sh` and `scripts/whoami.ps1`** — replace the event-log scan with a `GET /api/bots/whoami?colony=X&handle=Y` call. Inputs (`.bot-hive-identity`, env vars) unchanged. Outputs unchanged in format — same four lines. The `role= ` override in `.bot-hive-identity` (added in HV-122) still applies after the server call returns its value, locally on the client side.
- **`scripts/check-role.sh` and `scripts/check-role.ps1`** — new. Steps:
  1. Read `.bot-hive-role-cache` (single line `seat=N;role=ROLE`). If missing, treat as `seat=0;role=`.
  2. Call `GET /api/bots/whoami` for this bot.
  3. If seat or role differs from cache, print a role-change notice to stdout in a format the hook can inject as a system note:
     ```
     [BOT-HIVE] Role changed: you are now seat N of T, role: ROLE.
     Announce this to the operator before continuing.
     ```
  4. Update the cache file.
- **`scripts/heartbeat.sh` and `scripts/heartbeat.ps1`** — new. Background loop: `while true; do curl POST /heartbeat with {colony, handle}; sleep 300; done`. PowerShell equivalent uses `Start-Sleep 300`. The script writes its own PID to `.bot-hive-heartbeat.pid` at start. Designed to be backgrounded by the caller (`nohup … &` / `Start-Job`).
- **`.bot-hive-role-cache`** — small text file in worktree root. Single line: `seat=N;role=ROLE`. Written by `check-role`, deleted by shutdown.
- **`.bot-hive-heartbeat.pid`** — PID of the background heartbeat process. Written by `heartbeat`, deleted by shutdown.

## Notes

**No legacy fallback.** The old event-log-scan whoami stays in repo history but is gone from main after this ticket. The failure mode of the old code (everyone-is-bot-1) is bad enough that leaving it reachable as a fallback is worse than a clear "server down" error.

**Hook injection format is a contract.** The `[BOT-HIVE] Role changed: …` line format is the contract between `check-role` and the agent-host hook in HV-135. Don't change the prefix or the structure without updating HV-135.

**Server URL discovery.** All three scripts need to know the platform URL. Read from `$BOT_HIVE_API_URL` env var, fall back to `https://bot-hive-j0ax.onrender.com` (production). Document in HV-134.

**Heartbeat retry.** If a ping fails (server down, transient network), the loop logs to stderr and continues — does not exit. A bot doesn't need to die just because the server is briefly unreachable; the worst case is a 15-min reclaim if the server stays down that long.

**Out of scope:**
- Wiring the hook to the agent's host (Claude Code settings.json etc.) — HV-135.
- Updating `hive/bot-startup.md` to call `/join` and launch heartbeat — HV-134.
- `.gitignore` entries for the new cache/PID files — HV-134.

**Risk.** The hard cutover means a deploy ordering bug could leave bots unable to whoami. Land HV-130 + HV-131 first, deploy + smoke them, then merge this ticket. The FS dependency chain enforces this — don't bypass it.
