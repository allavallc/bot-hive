## Goal

Manage bot lifecycle so customers never run cleanup commands. When a bot ends — by the human ending its session, by going stale, or by being explicitly removed via the panel — the platform handles all the worktree / branch / identity-file teardown.

## Concrete UX

- **"Remove bot" affordance** on each row of the My Bot Team modal (FS-026). One click → confirmation modal → platform tears down the worktree, deletes the branch, removes the identity file. Bot gone.
- **Auto-cleanup of stale bots.** If a bot has had no events for 48h (the dormancy threshold from ADR-003), the same teardown fires automatically. Surface a notice in the panel: "Bot `<name>` was idle for 48h; cleaned up." So the human sees what happened.
- **Same-handle re-spawn already idempotent.** Add-a-Bot Step 1 already auto-removes the worktree if it exists at the same path — keep that working.
- **Orphan PR + branch cleanup when a ticket is reclaimed.** When `reclaim-stale-claims.{sh,ps1}` moves a ticket back to backlog, it must also close the open claim PR with a "ticket reclaimed; bot was stale" comment AND delete the remote branch. Today the script half-finishes: ticket goes back, PR + branch dangle indefinitely. Buzz hit this with wren's orphaned PR #76 / branch `hv-075-optimistic-column-placement` on 2026-05-09 — the next bot to claim the ticket couldn't `claim.ps1` cleanly because the open PR check refused.

## Done when

- [ ] My Bot Team modal has a per-row "Remove" button
- [ ] Click → confirmation → platform-side teardown (worktree remove, branch delete, identity file removed); panel updates within ~5s via SSE
- [ ] Cron task: scans event logs, identifies bots stale > 48h, performs the same teardown, posts a panel notice
- [ ] `reclaim-stale-claims.{sh,ps1}` extended to close the orphan PR + delete the remote branch as part of moving the ticket back to backlog. Idempotent (no-op if PR/branch already gone).
- [ ] No manual `git worktree remove` documented anywhere as a customer step. AGENTS.md / bot-startup.md / README.md updated accordingly.
- [ ] Local test: spawn a bot, click Remove, confirm worktree + branch + identity file all gone within ~5s. Spawn another, leave it idle 48h (or simulate by editing event-log timestamps), confirm cron sweeps it. Spawn a third, kill it before its claim PR merges, run reclaim-stale-claims, confirm the orphan PR is closed AND the branch is deleted.

## Out of scope (this ticket)

- Cross-machine teardown (if a bot is spawned on machine A and the human clicks Remove from machine B's panel, machine A's worktree won't be touched — that's a future capability requiring a sync agent on each machine)
- Pause / resume (separate idea, would live in ideas-to-consider)

## Notes

This ticket exists because during rung-1 testing, the orchestrator suggested manual `git worktree remove` to the human as an "optional" cleanup step. The human correctly pushed back: customers should never have to do that. The platform owns the lifecycle.

Depends on FS-026 (My Bot Team modal) for the UX surface, but the cron-based stale cleanup can ship independently.
