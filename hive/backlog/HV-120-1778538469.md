## Goal

User-marked-resolved anomalies stay resolved. The cron should treat human resolution as authoritative and not un-resolve.

## Root cause

`src/lib/swarm-health-cron.ts:61` — `onConflictDoUpdate` sets `resolvedAt: null` on every re-detection of the same `dedupKey`. The intent was "if the violation came back, un-resolve it" but it conflicts with human dismissal: there's no way to dismiss a recurring violation.

## Fix paths (pick one in PR)

- **Cheapest:** in `onConflictDoUpdate`'s `set` block, drop the `resolvedAt: null` line. Keep updating `lastSeenAt`, leave `resolvedAt` alone. If user resolved → stays resolved. If a human-resolved row's underlying violation truly went away and came back later, it'll show up the next time (already resolved) but won't auto-flip — the human can re-mark or it can stay archived.
- **More expressive:** add a `dismissed_by` column. Cron only resets `resolvedAt` when `dismissed_by IS NULL` (i.e. only system-resolved rows can be un-resolved on re-detection). Human dismissals are sticky.

Recommend the cheaper path. Sticky-by-default matches user expectation.
