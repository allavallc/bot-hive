## What

Fix the local board bug where the kanban/in-progress surface shows active bots, but the "My Bot Team" modal renders an empty state (or no bot rows) for the same project.

The first goal is to identify which source of truth is diverging:

1. board lane counts / badges
2. bot-team API response
3. modal client rendering / filtering
4. local-only project/session gating

Then make the modal reflect the same active-bot reality the board is already surfacing.

## Why

This breaks operator trust in the swarm UI. If one part of the board says bots are active and another says none exist, the human cannot tell whether bots are actually connected, whether the modal is stale, or whether local board state is partially broken.

Because the bug is visible on the local board now, we should capture it as a focused bug-fix ticket rather than bury it in a generic cleanup bucket.

## Done when

- [ ] Repro is documented from current local behavior: in-progress shows 2 bots, My Bot Team modal shows none
- [ ] Root cause is identified and fixed (data source mismatch, filtering bug, stale subscription bug, or render bug)
- [ ] On local dev, when the board shows active bots, the My Bot Team modal shows the same active bots for that project
- [ ] Empty state only appears when there are truly no active bots for the project
- [ ] If the issue was caused by client refresh/subscription behavior, bot rows update without requiring a hard reload
- [ ] Add or update a targeted test for the failing path if the relevant surface already has coverage nearby

## Desired output

A coder bot should land:

- the bug fix in the relevant board/modal/API path
- a small regression test where practical
- a brief note in the ticket/PR about the actual root cause so future swarm-state bugs are easier to classify

## How to test

1. Run local dev server.
2. Open a project board where the in-progress area shows active bots.
3. Open the My Bot Team modal.
4. Verify the modal lists the same active bots instead of showing none.
5. If applicable, start/stop a bot or change ticket state and confirm the modal refreshes correctly.

## Notes

- Prefer fixing the shared source of truth over patching the modal with special-case heuristics.
- Keep this scoped to the bot/team visibility mismatch; broader swarm-health or observability follow-ups can be separate tickets.
- Treat this as a real root-cause bug fix, not a cosmetic workaround.
