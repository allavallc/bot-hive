## Goal

Make the swarm-health panel actionable. Two pieces:

1. **Description + remediation per code.** Each invariant in `src/lib/swarm-health.ts` carries:
   - `description: string` — one line explaining what the rule checks
   - `remediation: string` — one line explaining what the operator should do (typically "tighten the rubric in `hive/skills/<role>.md`")
   The UI surfaces both inline under the bare code.
2. **"File hardening ticket" button** per row. Click → opens a backlog ticket form pre-populated with: the anomaly code, description, remediation, link to the firing ticket, and a suggested feature-set assignment (typically FS-023 or whichever rubric the violation maps to).

## Concrete changes

- **`src/lib/swarm-health.ts`** — extend each invariant config with `description` + `remediation` strings. Wire through to the `swarm_anomalies` table or compute on the API side.
- **`src/app/projects/[id]/swarm-health-panel.client.tsx`** — render description + remediation under the code; add a "File hardening ticket" button per row.
- **`src/app/api/projects/[id]/health/[anomalyId]/file-ticket/route.ts`** (new) — POST creates a backlog ticket file with pre-filled fields, opens a PR via the existing flow.
- Optional: gate the button to admins only (matches the rest of the panel's gating).
