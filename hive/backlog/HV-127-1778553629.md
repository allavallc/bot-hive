## Goal

The handle displayed on a card represents WHO IS CURRENTLY ACTING on it, not who originally claimed it. The display rule by ticket state:

- **`in-progress`** → `Assigned to:` (the coder who claimed). Today's behavior. Correct.
- **`in-review` AND `User-facing: no` AND `Reviewed by:` set** → the tester's handle (`<colony>.<handle>`). They're the current actor.
- **`in-review` AND `User-facing: no` AND `Reviewed by:` empty** → still show the dev bot's handle (no tester has picked it up yet). Or show "awaiting tester" placeholder.
- **`in-review` AND `User-facing: yes`** → the operator's GitHub login, WITHOUT the `.<handle>` suffix (humans don't have a colony bot handle). E.g. just `allavallc`.
- **`done`** → preserve the original coder's handle (credit history); optionally also show "approved by <reviewer>" as secondary text.

## Concrete changes

- **`src/app/projects/[id]/board.client.tsx`** — replace the single `extractHandle(fm["Assigned to"])` with a `currentActor(ticket)` helper that selects the right field based on `state` + `User-facing` + `Reviewed by`.
- **Human display** — when the actor is the operator (no `.<handle>`), pass through the GitHub login as-is. Need a way to know which login that is — likely the project's `session.user.name` (already gates the admin UI per FS-022). For non-admin viewers, the human isn't displayed at all.
- **Color coding** — `robotColor()` works on bot handles; for humans (no `.`) skip the color or use a neutral admin color.
