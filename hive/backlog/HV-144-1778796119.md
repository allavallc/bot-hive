## What

Make `handle` an optional query parameter on `GET /api/bots/stream`. When omitted, the server picks the next free handle from `hive/handles.txt` for the colony and uses it. Return the assigned handle in the `your-role` SSE event (already present in the event — just needs to work when handle is server-assigned).

## Why

Removes the only reason a bot needed to know its handle before connecting. Clients send `colony` only; the server resolves identity.

## Done when

- `GET /api/bots/stream?repo_full_name=…&colony=…` (no `handle`) connects successfully.
- Server reads `hive/handles.txt`, queries active bot handles for the colony, picks the first pool entry not currently active.
- If pool exhausted: appends lowest free numeric suffix to the first pool entry (e.g. `buzz-2`).
- `your-role` event includes `handle` field with the server-assigned value.
- `GET /api/bots/stream?…&handle=foo` still works (explicit handle → use as-is, existing behavior).
- Passing neither `colony` nor `repo_full_name` still returns 400.
- Existing tests pass; new test covers colony-only connect returning a handle.

## Implementation notes

- Read pool from `hive/handles.txt` via `readFileSync(join(process.cwd(), 'hive', 'handles.txt'))` — same pattern as `roles.ts`.
- Query active handles: `db.select({ handle: bots.handle }).from(bots).where(and(eq(bots.projectId, …), eq(bots.colony, …), eq(bots.status, 'active')))`.
- Pick first pool entry not in active set. Pool parsing: strip comment lines (`#`) and blank lines; trim each handle.
- Pass resolved handle to `connectBot(projectId, colony, resolvedHandle, connectionId)`.
- `your-role` event already sends `handle` (line 100 of `route.ts`) — no event-format change needed.
