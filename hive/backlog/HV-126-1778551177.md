## Concrete cause

`src/app/projects/[id]/board.client.tsx`:

```tsx
function WalkingRobot({ name }: { name?: string }) {
  const delay = useMemo(() => -Math.random() * 12, []);  // ← line 572
  return (...);
}

function WalkingHuman() {
  const delay = useMemo(() => -Math.random() * 14, []);  // ← line 579
  return (...);
}
```

`Math.random()` returns different values on the server (during SSR) vs the client (during hydration). React detects the mismatch in the rendered output and throws #418. The pre-existing code already had this bug, but HV-113 (PR #218) added more `<WalkingRobot />` instances to the in-review column (when `User-facing: no`), pushing the mismatch frequency past the threshold where React aborts the entire tree.

## Fix paths (pick one)

- **Cheapest:** move the random delay to CSS only — `:nth-child(odd)` / `:nth-child(3n)` style staggering, no JS randomness. No SSR/CSR mismatch possible because the server never calls JS for the value.
- **Slightly more flexible:** keep JS, but compute the delay in a `useEffect` and apply via `setState` after mount. SSR renders no inline style; client adds it post-hydration. Also fixes the hydration mismatch.

Recommend the CSS path — simpler, zero runtime cost, no extra render cycle.
