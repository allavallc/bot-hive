## Goal
Add an `Owner:` line to each feature-set file's header so the human can reserve a whole FS for a specific actor (a bot handle, themselves, or any future actor). Empty = open to anyone (default). Set = reserved.

## What's in

### FS-file convention
- Every FS file gets `**Owner**:` line under `**Status**:` (default blank)
- Three FSs reserved on this PR:
  - `feature-set-005-production-deploy.md` → `Owner: allavallc`
  - `feature-set-007-parallel-bot-coordination.md` → `Owner: allavallc-cc1`
  - `feature-set-014-agent-abstraction.md` → `Owner: allavallc-cc1`

### Protocol
- AGENTS.md DAG-walk gains a filter: skip tickets whose FS has a non-empty `Owner:` that isn't your handle
- HIVE.md gets a "Feature-set ownership" subsection explaining the field, the filter, and the reassignment-mid-flight rule

### Reassignment rule (when human says "you own FS-X now")
1. Named bot edits the FS file's `Owner:` line and pushes
2. Other bots **finish their in-progress ticket** in that FS (don't abandon)
3. Other bots stop picking new tickets from that FS
4. Forward-only — no clawback or rebase, just a tighter filter on next pull

### Bot CLI updates
- `scripts/my-work.{sh,ps1}` filters available backlog by Owner field (skips reserved FSs that aren't yours)
- `scripts/claim.{sh,ps1}` refuses claims into FSs owned by a different handle (early error, before any git ops)

## Why finish-current rather than hard-stop on reassignment
Abandoning a ticket mid-task creates a stale claim, wastes work, and forces a context-switch when another bot picks it up. Letting the current owner finish keeps continuity. Going forward, only the new owner picks new tickets. The user proposed this approach; it's the right call.
