## Goal
A canonical "hot files" list in `AGENTS.md` + `hive/HIVE.md`, and a convention that any agent about to open a PR touching one of those files first scans open PRs for conflicts. The check is `gh pr list` against the file path; the answer is either "rebase onto the existing branch" or "wait for it to merge."

## Why
This session burned ~6 PR-merge cycles resolving conflicts on `AGENTS.md` and `hive/HIVE.md` because two parallel branches kept appending sections in different places. github surfaces the conflict only at merge time — by then the PR has to be rebased manually. The pattern is predictable and preventable: every time any two parallel agents both edit a canonical doc, the second one gets DIRTY.

The fix is a pre-check, not a lock service. github's PR queue already tracks "what files does each open PR touch" — the convention is just "look before you write." No new infrastructure needed; pure agent-side discipline backed by `gh pr list`.

(A future "real" lock — broadcast a `lock` signal on the SSE channel — would be sub-second visibility, but it depends on bot HTTP auth that doesn't exist yet. Once bot tokens land, this convention can absorb that channel without changing.)

## Done when

### Hot files list (in AGENTS.md and HIVE.md)

A named list of files where parallel edits commonly conflict:

- `hive/HIVE.md`

The list lives in AGENTS.md so it's discoverable. HIVE.md describes the convention format-neutrally; the *specific* file list is repo-local and lives in AGENTS.md.

### Pre-edit check convention

Before opening a PR that edits any hot file, the agent runs:

```bash
gh pr list --state open --json number,headRefName,files \
  | jq -r --arg f "<hot-file-path>" \
      '.[] | select(.files[].path == $f) | "\(.number) \(.headRefName)"'
```

If the result is non-empty:
- **Best**: rebase your branch onto the existing PR's branch and add your changes; the second PR replaces the first as the canonical edit.
- **Acceptable**: wait for the existing PR to merge, then base off updated main.
- **Last resort**: pick different work.

If the result is empty: proceed normally.

### Helper script

A new `scripts/check-hot-files.sh` (and `.ps1`) takes a list of file paths on stdin (or args) and prints any open PRs that touch them. Returns non-zero if conflicts found, so it composes into pre-push hooks if anyone wants automation later.

```bash
# Usage:
./scripts/check-hot-files.sh AGENTS.md hive/HIVE.md
# Output (when conflicts exist):
#   AGENTS.md → PR #42 (hv-052-claim-rejected-first-impl)
#   hive/HIVE.md → PR #42 (hv-052-claim-rejected-first-impl)
# Exit 1.
```

## Out of scope
- Hard locks via the SSE signal channel — depends on bot HTTP auth (separate work). Convention is built so it can absorb that later.
- Pre-commit hook or git hook — invasive; the helper script is opt-in for now.
- Auto-rebase logic in the script — too easy to do something destructive; prompt the human / agent instead.

## Notes
- The list of hot files is curated, not auto-detected. Auto-detection (via git log churn analysis) is overkill until the curated list misses things.
- The convention pairs naturally with HV-050/051 (stale-PR watchdog): hot-file conflicts are exactly the "DIRTY" PRs that watchdog can't fix. Watching for them at edit-time prevents the DIRTY state from appearing in the first place.
