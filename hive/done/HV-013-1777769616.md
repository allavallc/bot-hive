## Goal
Style `/login`, `/dashboard`, and `/projects/new` with the same Bot Hive editorial-brutalist tokens used on the board.

## Why
HV-007 scoped to "board only" so the demo could ship faster. Users now see a polished kanban but plain unstyled HTML on the screens leading up to it. The seam looks unfinished.

## Done when
- `/login`, `/dashboard`, `/projects/new` use the dark theme, terracotta accent, and font stack already loaded in `src/app/layout.tsx`.
- A shared `src/app/globals.css` (or a small CSS module per page) carries the tokens; no @import font calls (`next/font` already loads them).
- Visual rhythm matches the board: `--line` hairlines, `--accent` for links/highlights, mono small-caps for metadata, display font for h1/h2.
- Sign-in button on `/login` is styled like the Bot Hive-style outlined CTA.
- Dashboard project list looks like a card list with hairline rules, not a default `<ul>`.

## Desired output
The whole app feels like one product, not a kanban grafted onto a dev scaffold.

## Success signals
- A first-time visitor signing in for the first time doesn't perceive a style break between login → dashboard → board.

## Failure signals
- Tokens drift: `--accent` hex differs across pages.
- Adding new pages later requires re-stating the same CSS each time.

## Tests
- Manual: walk the sign-in → dashboard → connect → board flow; verify visual consistency.

## How to test
1. Build prod (`npm run build && npm run start`) or dev (`npm run dev`).
2. Visit `http://localhost:3000` — should redirect to `/login` (signed out) or `/dashboard` (signed in).
3. `/login`: dark bg, Bot Hive wordmark in masthead, kicker → page title "Live kanban for your hive of bots." → lede → outlined "Sign in with GitHub" CTA. The HV-011 sign-out hint banner sits above with hairline border.
4. `/dashboard`: same wordmark + masthead with "Sign out" button on the right. Kicker "Dashboard / <name>", page title "Your projects", numbered hairline list of repos. Hover slides each row right and turns the title accent.
5. `/projects/new`: same chrome + ← Dashboard breadcrumb, kicker, page title, lede, install CTA.
6. `/projects/[id]`: board unchanged from HV-007 (its own CSS module).
7. Reload browser — favicon shows the hexagonal hive with three bees.

## Notes
- Use a single `globals.css` rather than per-page modules so tokens stay in one place.
- Out of scope: full responsive design pass, accessibility audit (file separately if needed).
- Out of scope: redesigning the board (HV-007's CSS module stays).

## Resolution
- 9 files: `src/app/globals.css` (new — design tokens at `:root`, universal box-sizing reset, body bg), `src/components/page-shell.tsx` (new — `<PageShell>` wrapper + `<SignOutForm>`), `src/components/page-shell.module.css` (new — chrome + reusable primitives: kicker, pageTitle, lede, btnOut, btnGhost, list/listItem, hint), `src/components/wordmark.tsx` (new — Bot Hive SVG with `currentColor` letters), `src/app/icon.svg` (replaced with hexagonal hive logo mark), `src/app/page.tsx` (root `/` now redirects to /dashboard or /login based on session), `src/app/login/page.tsx`, `src/app/dashboard/page.tsx`, `src/app/projects/new/page.tsx` (all three composed of PageShell + ui primitives, ~30-50 lines each).
- **Reuse pattern:** every page imports `pageShellStyles as ui` and references shared classes. Adding a new page = new file with `<PageShell>` + content using `ui.kicker`/`ui.pageTitle`/`ui.btnOut`. No per-page stylesheet duplication.
- **Wordmark color handling:** SVG fills swapped from hardcoded `#1A1F2E` (dark navy, invisible on dark bg) to `currentColor` so the brand link's `color: var(--ink)` propagates. Yellow hexagon + bee details keep their original colors.
- **Verified by user** ("approved") after walking through `/login → /dashboard → /projects/new → /projects/[id]` flow with the redesigned chrome + new wordmark + favicon.
