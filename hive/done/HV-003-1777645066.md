## Goal
Wire Better Auth with the GitHub provider so a user can sign in, see `/dashboard`, sign out, and have protected routes redirect to `/login`.

## Why
Every project row needs an owner. GitHub OAuth specifically because the same identity later installs the GitHub App on user repos.

## Done when
- `src/lib/auth.ts` configures Better Auth + GitHub provider + Drizzle adapter.
- `src/lib/auth-client.ts` exposes `authClient` for client-side sign-in.
- `src/app/api/auth/[...all]/route.ts` exposes the handler.
- `/login` shows "Sign in with GitHub" (client component using `authClient.signIn.social`).
- `/dashboard` reads the session server-side, shows the user's name, shows "No projects yet".
- `src/middleware.ts` redirects unauthenticated `/dashboard` and `/projects/*` to `/login`.
- Sign-out revokes the GitHub OAuth grant, clears the session, redirects to `/login`.

## Desired output
Click GitHub → authorize → land on `/dashboard` with name visible. Closing and reopening the tab keeps the session.

## Success signals
- `users` row created on first sign-in; `sessions` row tracks the session and is deleted on sign-out.
- OAuth scope is the minimum needed (no `repo` — that comes via the App in HV-004).

## Failure signals
- Stale `sessions` rows persist after sign-out.
- Middleware misses a route — `/projects/new` reachable signed-out.
- Email missing because we didn't request `user:email`.

## Tests
- Manual: sign in, sign out, hit `/dashboard` signed-out (must redirect).
- Manual: two browsers → one `users` row, two `sessions` rows.

## Notes
- The OAuth app is **separate** from the GitHub App in HV-004. Same identity, different registrations.
- Callback URL: `http://localhost:3000/api/auth/callback/github`.
- Out of scope: account deletion, multi-provider, org membership checks.

## Resolution
- 6 files shipped: `src/lib/auth.ts`, `src/lib/auth-client.ts`, `src/app/api/auth/[...all]/route.ts`, `src/app/login/page.tsx` (client component), `src/app/dashboard/page.tsx`, `src/middleware.ts`.
- `auth.ts` config: `baseURL`, explicit `secret`, `trustedOrigins`, Drizzle adapter, GitHub provider with `scope: ["read:user", "user:email"]`, `emailAndPassword: { enabled: false }`.
- **Server-action sign-in failed with `state_mismatch`** — Better Auth's `auth.api.signInSocial` from a server action sets state cookies on its internal Response that don't propagate to Next.js's outgoing response, so the OAuth state cookie never reached the browser. Pivoted login page to a client component using `authClient.signIn.social()`. Sign-out stayed as a server action (no state cookie issue).
- **Security hardening (added beyond original DoD):** sign-out also calls `DELETE https://api.github.com/applications/{client_id}/grant` with HTTP Basic (client_id:client_secret) to revoke the user's OAuth grant. Without this, a coworker on the same machine could click "Sign in with GitHub" after the user signed out and silently land in their account. With grant revoke, GitHub now requires the consent screen on every sign-in — the next user sees *whose* account is about to be authorized. Verified manually.
- **Manual verification passed:** sign-in lands on `/dashboard` with name. Sign-out clears the session row + cookie and redirects to `/login`. Signed-out access to `/dashboard` and `/projects/*` redirects via middleware. Re-sign-in shows GitHub consent screen (proof the grant was revoked).
- HV-011 filed for the "also sign out of GitHub" UX hint (deferred until HV-007 lands the styled login page).
