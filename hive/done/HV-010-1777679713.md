## Goal
Install Vitest and write the two HV-002 schema constraint tests that were deferred when Vitest was missing.

## Why
HV-002 closed on manual verification because Vitest wasn't installed. The constraint tests still belong in CI before HV-005 starts inserting real rows.

## Done when
- `vitest` + `@vitest/ui` (optional) in devDeps; `npm test` script in `package.json`.
- `vitest.config.ts` with the test-file glob and `globals: true` if we want to skip imports.
- `src/db/schema.test.ts` runs against the local Postgres (uses `DATABASE_URL`), wraps each test in a transaction that rolls back on teardown so tests are idempotent and don't pollute the dev DB.
- Test 1: insert two `tickets` rows with the same `(project_id, hv_id)` → second insert throws on the unique constraint.
- Test 2: insert two `webhook_deliveries` rows with the same `(project_id, delivery_id)` → second insert throws on the composite PK.
- `npm test` exits 0 locally.

## Desired output
`npm test` runs the constraint tests in <2s and they pass.

## Success signals

- Tests don't leave rows in the dev DB after they run.

## Failure signals

## Tests
- Self-referential — the two tests above are the deliverable.

## Notes
- Strategy: use `db.transaction(async (tx) => { ...; throw new Rollback(); })` and catch the rollback marker so the assertion still runs but the tx aborts.
- Alternative considered: spin up a separate `bot_hive_test` DB. Rejected — the dev DB + transaction rollback is enough for two unit tests, and it avoids a second Postgres setup.
- Out of scope: integration tests against the GitHub API, end-to-end browser tests.

## Resolution
- 3 files: `vitest.config.ts` (new — node env, dotenv setup, `@/` alias), `src/db/schema.test.ts` (new — two constraint tests), `package.json` (added `vitest` devDep + `"test": "vitest run"` script).
- **Final isolation strategy**: changed from "transaction-rollback" to "unique-IDs + cleanup in afterEach". Each test gets a `randomUUID`-suffixed `user.id`, creates a project under it, runs the assertion, then `delete from user` cascades through projects → tickets / webhook_deliveries. Cleaner than fighting Postgres' aborted-transaction state after a constraint violation.
- **Both tests green in 530ms** — `npm test` runs vitest once and exits. CI-ready.
- Drizzle's postgres-js client throws on the unique-constraint / PK violations as expected (`tickets_project_hv_unique` and `webhook_deliveries_project_id_delivery_id_pk`).
