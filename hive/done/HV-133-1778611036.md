## Goal

Replace the event-log-scanning `whoami` with a server call and ship the two new scripts the boot/hook lifecycle needs (`check-role` for in-session role-change detection, `heartbeat` for liveness).

## Concrete changes

- **`scripts/whoami.sh` and `scripts/whoami.ps1`** — replace the event-log scan with a call to `GET /api/bots/whoami?repo_full_name=…&colony=…&handle=…`. Inputs (`.bot-hive-identity`, env vars) unchanged. Repo full name is derived from `git remote get-url origin` and parsed to `owner/repo` (handle both HTTPS and SSH URL shapes). Output format unchanged — same four lines (`actor:`, `colony bots active:`, `role:`, `read these skill files:`). The `role=` override in `.bot-hive-identity` (HV-122) still applies client-side after the server response.
- **`scripts/check-role.sh` and `scripts/check-role.ps1`** — new. Steps:
  1. Read `.bot-hive-role-cache` (single line `seat=N;role=ROLE`). If missing, treat as `seat=0;role=`.
  2. Call `GET /api/bots/whoami` for this bot (same repo/colony/handle resolution as `whoami`).
  3. If seat or role differs from cache, print to stdout in a format the hook can inject as a system note:
     ```
     [BOT-HIVE] Role changed: you are now seat N of T, role: ROLE.
     Announce this to the operator before continuing.
     ```
  4. Update the cache file.
  5. Exit 0 in all success paths (silent if unchanged, prints notice if changed).
- **`scripts/heartbeat.sh` and `scripts/heartbeat.ps1`** — new. Background loop: ping `POST /api/bots/heartbeat` with `{repo_full_name, colony, handle}` every 5 min. POSIX uses `while true; do curl …; sleep 300; done`. PowerShell uses `while ($true) { Invoke-RestMethod …; Start-Sleep 300 }`. The script writes its own PID to `.bot-hive-heartbeat.pid` at start. Designed to be backgrounded by the caller (`nohup … &` / `Start-Job`).
- **`.bot-hive-role-cache`** — small text file in worktree root. Single line: `seat=N;role=ROLE`. Written by `check-role`, deleted by shutdown.
- **`.bot-hive-heartbeat.pid`** — PID of the background heartbeat process. Written by `heartbeat`, deleted by shutdown.
- **Server URL discovery** — read `BOT_HIVE_API_URL` env var, fall back to `https://bot-hive-j0ax.onrender.com` (production). The fallback string is the only place the production URL is hardcoded.

## Notes

**Hard cutover, no legacy fallback.** The old event-log-scan whoami stays in repo history but is gone from main after this ticket. The failure mode of the old code (everyone-is-bot-1) is bad enough that leaving it reachable as a fallback is worse than a clear "server down" error message.

**Hook injection format is a contract.** The `[BOT-HIVE] Role changed: …` line format is the contract between `check-role` and the agent-host hook in HV-135. Don't change the prefix or structure without updating HV-135.

**Heartbeat retry policy.** If a ping fails (server down, transient network), the loop logs to stderr and continues — does not exit. A bot doesn't need to die just because the server is briefly unreachable; the worst case is a 15-min sweep-on-request reclaim if the server stays unreachable that long.

**Why repo name parsing in the script.** Scripts don't know the platform's internal `projects.id` UUID. They derive `owner/repo` from `git remote get-url origin`, the server resolves to `projects.id` via the `githubRepo` column (see `src/lib/webhook.ts:39` for the existing lookup pattern).

**Out of scope:**
- Wiring the hook to the agent's host (Claude Code `settings.json` etc.) — HV-135.
- Updating `hive/bot-startup.md` to call `/join` and launch heartbeat — HV-134.
- `.gitignore` entries for the new cache/PID files — HV-134.

**Risk.** Hard cutover means a deploy ordering bug could leave bots unable to whoami. The FS-028 ticket chain (HV-130 + HV-131 deploy → smoke → then merge HV-133) prevents this; don't bypass the order.
