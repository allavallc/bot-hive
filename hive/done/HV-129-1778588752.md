- **Verification**: spawning a bot via the Add-a-Bot button (or by writing `.bot-hive-kickoff` to a worktree by hand) makes that bot bootstrap on its first turn WITHOUT the operator typing `start the hive`. A bot in a worktree with no marker file and no `start the hive` phrase still waits silently. After consuming the marker, the file is deleted from the worktree.
- **Failure mode**: today the kickoff is gated by a single trigger — the operator typing `start the hive` in chat. Each LLM session is a separate conversation with no shared state, so when the operator spawns a second bot (buzz) after kicking off the first (wren), the second bot also waits for the phrase. The operator has to type it again, in the new terminal, for every new bot. Friction scales linearly with colony size and surprises new operators ("but I already typed it!").

## Goal

Bots accept TWO equivalent kickoff triggers; either one bootstraps the session:

1. **Operator types `start the hive`** (or any equivalent phrase) in chat — today's behavior, unchanged.
2. **`.bot-hive-kickoff` file present at the worktree root** — equivalent to the phrase, consumed (deleted) on bootstrap.

The Add-a-Bot button writes `.bot-hive-kickoff` alongside `.bot-hive-identity` in the new worktree. The spawned bot reads its first turn, sees the marker, bootstraps, deletes the marker. Operator types nothing.

The phrase remains the canonical, human-friendly trigger for the operator's main checkout (where there's no Add-a-Bot spawn flow). Both paths converge on the same `bot-startup.md` numbered checklist.

## Concrete changes

**1. `hive/bot-startup.md`** — rewrite the opening paragraph and step 1:

- Opening: "Execute these steps top-to-bottom on session start when EITHER trigger fires:
  - the operator types `start the hive` (or equivalent) in chat, OR
  - a `.bot-hive-kickoff` marker file exists at the worktree root.
  If neither trigger has fired, wait silently."
- New step 0 (before "Ensure identity exists"): "Check for `.bot-hive-kickoff` at the worktree root. If present: continue. Delete the file at the end of step 3 (after announcing identity) so it's a one-shot. If absent AND the operator hasn't typed the phrase: wait silently — do not proceed."

**2. `AGENTS.md`** — replace the "Kickoff (do this first)" section with the dual-trigger language. Cross-reference `bot-startup.md`.

**3. `CLAUDE.md`** — the stub gets one extra line in the Kickoff paragraph: "Kickoff is either the phrase `start the hive` in chat OR the presence of `.bot-hive-kickoff` at the worktree root." Stay agent-neutral.

**4. Add-a-Bot spawn flow** — update the worktree-setup code path that writes `.bot-hive-identity` to also write `.bot-hive-kickoff` (empty file is fine; presence is the signal). Locate via `grep -r "bot-hive-identity" src/` to find the spawn-time write. The marker is added to `.gitignore` so it's never committed (it's a local, one-shot signal).

**5. `.gitignore`** — add `.bot-hive-kickoff`.

**6. `scripts/whoami.{sh,ps1}`** — no change. (The marker is a kickoff signal, not an identity signal. whoami still keys off `.bot-hive-identity`.)
