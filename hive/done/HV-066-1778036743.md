## Goal
Automatically detect and reclaim in-progress tickets whose `Last touched:` timestamp is older than the swarm's 2-hour stale threshold. The bot-side convention exists in HIVE.md; this ticket adds enforcement: a script that scans `hive/in-progress/`, finds stale ones, and either reports them or moves them back to `backlog/` (resetting Status, clearing Assigned to). Wired to a GitHub Actions cron that runs every 30 min as a backstop when no agents are online.

## Why
HIVE.md describes the 2-hour `Last touched:` rule and says "any agent may reclaim a stale claim on session start." But:

1. There's no enforcement when no agents are around. CC2's session ended mid-work; their in-progress ticket sat untouched until I happened to notice.
2. There's no mechanical primitive — agents read HIVE.md and have to remember to do the scan manually.
3. The cron we already added for stale PRs (HV-051) is the natural pattern; this is the ticket-level companion.

The pair (HV-051 + HV-066) gives the swarm a passive recovery layer: PRs that go BEHIND get auto-updated, claims that go stale get auto-reclaimed. No human intervention, no convention-burden on the next agent to clean up after the previous.

## Done when

### Script
- `scripts/reclaim-stale-claims.sh` (and `.ps1`) scans `hive/in-progress/*.md`:
  - For each ticket file, parse the `Last touched:` ISO timestamp.
  - If older than 2 hours, log a one-line warning: `STALE: HV-XXX (last touched <time>, assigned <handle>)`.
  - With `--reclaim` flag: edit the ticket's frontmatter (clear `Assigned to:`, clear `Started:`, set `Status: open`, add `**Reclaim reason:** stale claim from <handle>; last touched <ISO>`), `git mv` the file from `in-progress/` to `backlog/`, append to `events.log`, and commit + push as a small dedicated PR.
  - Without `--reclaim`: dry run only; prints the list and exits.
  - Exit code: 0 if no stale claims found or all reclaimed cleanly; 1 if stale claims found in dry-run mode.

### GitHub Actions cron
- `.github/workflows/reclaim-stale-claims.yml` runs every 30 min:
  - Checks out the repo.
  - Runs `./scripts/reclaim-stale-claims.sh --reclaim`.
  - If anything was reclaimed, the script's commit + PR + auto-merge handles the propagation.
  - Permissions: `contents: write`, `pull-requests: write`.

### Convention update
- `AGENTS.md` and `hive/HIVE.md` "Last touched" subsections add a one-liner: "A scheduled job (`./.github/workflows/reclaim-stale-claims.yml`) runs every 30 min as a backstop. Active agents may still reclaim manually on session start — the cron is the safety net, not the primary path."

### Verification
- Manual dry-run: `./scripts/reclaim-stale-claims.sh` against current `hive/in-progress/` — prints any stale tickets (or nothing).
- typecheck + lint + tests + build all clean (no source code changes — script + workflow only).
- Cron file syntax valid (no missing `permissions:` block, valid cron expression).

## Out of scope
- **Notifying the bot** that originally claimed the ticket. The reclaim is silent; the original bot's session is over by definition (that's why the ticket went stale). If a bot's still alive when their work is reclaimed, they'll notice on their next pull and adapt — no mechanism needed.
- **Tracking how many times a ticket has been reclaimed.** A ticket reclaimed 5 times is suspicious, but counting is more bookkeeping than this is worth.
- **Different thresholds for different effort sizes.** A 2h threshold for an XL ticket is too aggressive; for an XS ticket it's plenty. Defer until we see a real complaint about the uniform threshold.
- **Reclaim of in-review tickets.** The `Last touched:` rule is for in-progress only; in-review is between the bot and the human.

## Notes
- The script needs `gh`, `git`, `jq` available — all present in the GitHub Actions ubuntu runner by default.
- For the local PowerShell variant, prefer `Get-Date` parsing over external tools to keep it self-contained.
- The Reclaim PR should auto-merge to keep the recovery flow zero-touch. Use the same `gh pr merge --auto --squash` pattern as the stale-PR watchdog.
- This convention pairs naturally with HV-061 (presence). When the swarm panel can render presence + active claims (later UI work), a stale claim with no presence ping is visibly orphaned long before the 2h threshold.
