## Goal
Turn "bot reads docs and follows them carefully" into "bot runs `./scripts/claim.sh HV-053` and the script does it right." Highest-leverage missing piece per the post-HV-090 honesty pass — the protocol is enforced where the platform mediates, but everywhere else it's still convention. CLI helpers make compliance trivial regardless of how carefully the bot read AGENTS.md.

## What's in

### `scripts/my-work.{sh,ps1}` — session-start helper
Runs `git pull --rebase` (mandatory pre-action freshness), then surfaces in order:
1. Bot's own rejected work in `hive/in-progress/` (HV-052 pre-claim ritual)
2. Bot's other in-progress tickets
3. Notes addressed to bot in `hive/notes-to-bots/*.log` from the last 24h (filters `@<handle>` and `@swarm`)
4. Recent swarm activity (last 50 lines from merged `hive/events/*.log`)
5. Available backlog leaves filtered by Blocked-by and FS-Status (skips tickets whose FS is `future` / `done`)

### `scripts/claim.{sh,ps1}` — end-to-end claim
- `git pull --rebase origin main`
- Verifies ticket is in `hive/backlog/`
- Verifies no open PR already references the ticket id (`gh pr list --search`)
- Creates branch `hv-<id>-claim`, moves file to `in-progress/`, patches frontmatter (Status / Assigned to / Started / Last touched)
- Appends `<ts> <hv-id> claim <handle>` to `hive/events/<handle>.log`
- Commits, pushes, opens auto-merging PR. Open PR is the claim signal — visible to peers via `gh pr list` immediately.

### `scripts/note.{sh,ps1}` — bot → human note
- Sanitizes tabs/newlines (TSV format)
- Validates 280-char limit
- Appends TSV line to `hive/notes-to-humans/<handle>.log`
- Commits + pushes + opens auto-merging PR

### AGENTS.md bot-CLI section
Top-of-file pointer block describing the three scripts and the `BOT_HIVE_HANDLE` env var requirement. Bots see this on first read of AGENTS.md.

## What this PR does NOT do
- Does not call the soft-fence claim API. That requires session auth which bots running in user terminals don't have access to. The open PR + `gh pr list` is the visible-claim signal at bot scope; the platform's soft-fence is for the human-side board UI. Cross-bot collision rejection still works because the second bot's `claim.sh` will see the first's open PR and bail.
- Does not implement bot CLI auth. Bots use the user's existing git+gh auth (already set up locally) for everything they touch.
- Does not enforce that bots use these scripts — they're the recommended path; bots that ignore them and construct git ops by hand can still do so.
