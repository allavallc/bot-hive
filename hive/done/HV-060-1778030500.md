## Goal
Update `docs/DEPLOY.md` Step 2.3 (Repository permissions) to include "Pull requests: Read & write", and add a note that adding a permission to an existing App requires re-approving the install on github.com.

## Why
HV-046 introduced accept/reject endpoints that create PRs via the GitHub App's installation token. The runbook only listed Contents + Metadata, so operators following it from scratch will produce a broken App that returns "failed to create PR". Also establishes the convention: when a PR adds a new infra requirement, that PR owns the doc update.

- Step 2.3 lists Pull requests: Read & write alongside Contents and Metadata
- A note explains that adding permissions to an existing App requires re-approving the install
