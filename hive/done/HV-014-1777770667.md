## Goal
Add a small walking-robot SVG that paces along the dashed border of every `in-progress` card, mirroring the bot-horde reference board.

## Why
The walking robot is the iconic visual in bot-horde (called out specifically in `docs/HISTORY.md` as one of the things "carried forward unchanged" across two project renames). Without it, the in-progress column looks generic — with it, the board looks like the product it descends from.

## Done when
- An inline SVG mascot (single color, ~24px) renders inside each `data-state="in-progress"` card.
- A CSS `@keyframes` animation moves the mascot along the dashed border edge — top-left → top-right → bottom-right → bottom-left → loop. Speed: ~12 second cycle.
- One mascot per assigned bot (read `Assigned to` field), with a stable color hash per name (e.g. `claude` always green, `sarah` always pink) so two bots on the same board are visually distinct.
- Animation respects `prefers-reduced-motion`: if reduced, mascot sits static at one corner.
- Animation runs only while the card is on screen (use `IntersectionObserver` or CSS-only `animation-play-state`).

## Desired output
The "in progress" column visibly hums — the user can see at a glance which bot is on which ticket without reading any text.

## Success signals
- Two cards with two different assignees show two different mascot colors.
- A card with no `Assigned to` falls back to a single accent-color mascot.

## Failure signals
- Mascot animation kills frame rate on low-end devices.
- Animation continues running for off-screen cards (battery drain).
- Mascot overlaps card content (positioning bug).

## Tests
- Manual: open the board with 3+ in-progress cards; verify smooth animation, distinct colors per assignee.
- Manual: enable Windows "Reduce motion" → confirm mascots freeze.

## How to test
1. Build prod (`npm run build && npm run start`), open `/projects/[id]`.
2. Move 2-3 tickets to `hive/in-progress/` with different `Assigned to` values, push.
3. Watch in-progress column: mascots walk along the dashed borders.
4. Enable system "reduce motion" preference, reload — mascots should be static.

## Notes
- bot-horde's reference uses pixel-art mascots inlined as SVG `<symbol>` defs. Same approach here keeps it dependency-free.
- Color hash: `hash(name) % palette.length` over a curated palette (5-6 colors). Don't randomize per page load.
- Out of scope: drag-to-reorder, mascot interactions (hover tooltips, click-to-jump-to-bot-profile).

## Resolution
- Implemented inside `src/app/projects/[id]/board.client.tsx` as a `<RobotMascot name={assignee} />` component, rendered conditionally only when `ticket.state === "in-progress"`.
- SVG ported verbatim from bot-horde demo source: 18×18 viewBox, antenna + body + two eyes + two legs, all filled with `currentColor` so the per-bot color flows through.
- 8-color palette + djb2-style hash on the assignee name (matches bot-horde's `crabColor`): `["#ef4444","#f97316","#eab308","#22c55e","#06b6d4","#3b82f6","#8b5cf6","#ec4899"]`. Stable per name. Falls back to `#22c55e` (green) when no assignee.
- CSS keyframe `botRobotWalk` paces the mascot around the card edge in 12s (top-left → top-right → bottom-right → bottom-left → loop). Card has `position: relative` only on `[data-state="in-progress"]`.
- Per-instance `animation-delay` randomized via `useMemo(() => -Math.random() * 12, [])` so multiple bots aren't synchronized.
- `@media (prefers-reduced-motion: reduce)` clamps `animation: none` and pins to top-left.
- Drop-shadow on the mascot uses the per-bot color at 0.6 alpha for a subtle glow.
- Verified visually after the bot-horde reference fetch confirmed "robot" semantics; HV-013 in-progress card showed the green `claude` robot pacing as expected.
