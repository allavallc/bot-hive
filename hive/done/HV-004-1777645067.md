## Goal
Register the "Hive (local dev)" GitHub App and write a typed Octokit factory that mints installation tokens on demand.

## Why
GitHub Apps give per-repo, refreshable, narrowly scoped access. OAuth tokens (HV-003) are user-scoped and over-broad.

## Done when
- GitHub App registered on `allavallc` with: Homepage `http://localhost:3000`, Setup URL `http://localhost:3000/projects/install/callback`, Webhook URL = smee.io tunnel, Webhook secret in `.env`, permissions `Contents: Read` + `Metadata: Read`, events `Push` + `Installation` + `Installation repositories`.
- `.env` carries `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY_PATH` (file-on-disk pattern, not inline PEM), `GITHUB_APP_WEBHOOK_SECRET`, `SMEE_URL`.
- `src/lib/github.ts` exports `appOctokit()` (App-level) and `installationOctokit(id)` (installation-scoped, with token cache valid until ~10 min before expiry).
- `src/app/api/github/test/route.ts` lists the signed-in user's installations and accessible repos.
- `npm run smee` runs `smee --target http://localhost:3000/api/github/webhook`.

## Desired output
Hit `/api/github/test` while signed in → see at least one installation and its repos.

## Success signals
- Installation tokens cached in memory; not minted on every API call.
- smee.io forwards a "redeliver" from the App settings page to the dev server.

## Failure signals
- Webhook secret mismatch → every delivery fails HMAC in HV-006.
- Private key fails to load due to CRLF/quoting in `.env`.
- Server starts despite invalid private key, then errors mid-request.

## Tests
- Manual: install App on a test repo, hit `/api/github/test`.
- Manual: redeliver a test webhook → 404 at `/api/github/webhook` is fine here (the route lands in HV-006); confirms tunnel works.
- Unit: `installationOctokit(id)` called twice within a minute returns the cached token.
- Manual: invalid private key fails fast at startup with a clear error.

## Resolution
- 5 files: `src/lib/github.ts`, `src/app/api/github/test/route.ts`, `scripts/smee.mjs`, `package.json` (smee script + deps), `.env.example` (renamed `GITHUB_APP_PRIVATE_KEY` → `GITHUB_APP_PRIVATE_KEY_PATH`).
- **Private key storage:** matches the user's existing GCP-key convention — `.pem` file at `~/.github-app-keys/hive-local.pem`, `.env` carries the path string only. Cross-platform `~` expansion via `os.homedir()`. Same code shape works in prod (swap path for secret-manager fetch).
- **Token cache:** in-memory `Map<installationId, { token, expiresAt }>` plus an `inFlight` `Map<installationId, Promise>` for request collapsing. Concurrent callers for the same installation share a single mint. Tokens reused for ~55 min (5-min buffer before GitHub's 1-hour expiry). Failed mints don't pollute the cache. Multi-instance prod: each process has its own cache (acceptable — GitHub allows multiple valid tokens per installation).
- **Octokit packaging:** `@octokit/app` for the App + JWT signing + `app.octokit` (App-level instance). `@octokit/core`'s `Octokit` for installation-scoped instances (constructed fresh per call with the cached token). `@octokit/app` does NOT re-export `Octokit` — added `@octokit/core` as a direct dep.
- **Verified:** GET `/api/github/test` (auth-gated) returned `{"installations":[{"installationId":128952205,"account":"allavallc","repos":["allavallc/bot-hive"]}]}` — App auth, JWT signing, key loading, installation token mint, and installation-scoped repo listing all work end-to-end. Smee tunnel forwarding from `https://smee.io/q7rfDrJHJpgyG9Tr` to `localhost:3000/api/github/webhook` (route lands in HV-006).
- The bot-hive GitHub repo exists on `allavallc/bot-hive` and is the test target for the App installation.
- The `installationOctokit` cache test is deferred to HV-010 (no Vitest yet).
