## Goal
Render the kanban for a connected project and refresh it live from the webhook pipeline via SSE.

## Why
This is the deliverable a user sees. Phases 1.1–1.6 are infrastructure; 1.7 is the product.

## Done when
- `/projects/[id]` is a server component that reads tickets from DB and renders the kanban.
- `board.client.tsx` subscribes to `/api/projects/[id]/stream`; on event, refreshes the board state.
- `/api/projects/[id]/stream` is the SSE endpoint; auth-gated to the project owner.
- `src/lib/broadcast.ts` is an in-memory pub/sub keyed by project; `webhook.ts` calls `broadcast(projectId)` after upsert.
- 5-column grid (`backlog`, `in-progress`, `in-review`, `done`, `blocked`) plus toggleable 6th (`not-doing`).
- Filter bar: priority, effort, feature set, "Ready only" — same semantics as Bot Hive's `board.html`.
- Cards expand on click to show full ticket body (Goal, Why, Done when, Desired output, Success signals, Failure signals, Tests, Notes).
- Visual matches `plan/style-guide.md`: dark theme, accent `#c4724a`, Big Shoulders Display + Atkinson Hyperlegible + Inter + JetBrains Mono, square borders, hairline rules, mono small-caps labels.

## Desired output
Push a commit that moves a ticket → card slides to the new column within ~5s without manual refresh. Filters narrow the view immediately.

## Success signals
- SSE reconnects after `next dev` HMR or a network blip without a page reload.
- "Ready only" hides tickets whose `Blocked by` references an unfinished blocker.
- Card detail is keyboard-accessible (Enter/Esc to expand/close).

## Failure signals
- SSE leak: closed clients aren't removed from the pub/sub Set, memory grows unbounded.
- Server component caches stale data; first paint is older than the latest webhook.
- Filter state is lost on board refresh.

## Tests
- Manual (acceptance loop, `User-facing: yes`): push add/move/delete on the fixture repo and watch the board.
- Manual: open two tabs, push once, both update.
- Manual: kill the dev server, restart, board still reconnects.
- Manual: visual diff against Bot Hive's `board.html` reference.

## Notes
- In-memory pub/sub is fine for single-process local dev. Production multi-instance broadcast is Phase 2.
- Polling fallback is **not** added now — SSE reconnect handles transient drops.
- The board is the renderer. Once this ships, the `Bot Hive` `build.sh` / `validate.py` static-board path is permanently retired for Bot Hive's own use.

## How to test
1. Start the production server (`npm run build && npm run start`).
2. Sign in at `http://localhost:3000/login`.
3. From `/dashboard`, click the connected project → lands on `/projects/[id]`.
4. Verify the kanban renders 5 columns (Backlog, In progress, In review, Done, Blocked) with cards distributed by their folder under `hive/`.
5. Click a card — body should expand inline showing Goal/Why/Done when/etc.
6. Click any filter chip — URL updates with `?priority=...` etc., visible cards narrow.
7. Toggle "Show not-doing" — 6th column appears/disappears.
8. In another terminal, `git mv hive/backlog/HV-XXX-*.md hive/done/` (or any folder change), commit + push. Within ~5s, the corresponding card slides to the new column on the open board tab without manual refresh.

## Resolution
- 5 board files + 1 layout edit: `src/app/projects/[id]/page.tsx` (server, initial DB fetch + auth gate), `src/app/projects/[id]/board.client.tsx` (client — filters via URL params, SSE subscription, inline card expansion, Esc to close), `src/app/projects/[id]/board.module.css` (Bot Hive tokens), `src/app/api/projects/[id]/stream/route.ts` (SSE with keepalive + broadcast subscribe + cancel cleanup), `src/app/api/projects/[id]/tickets/route.ts` (JSON refetch on SSE event), modified `src/app/layout.tsx` for `next/font/google`.
- **Filter state in URL** (`?priority=&effort=&feature=&ready=1`) — sharable, survives reload, and is the primary state-persistence layer.
- **"Ready only" filter** computed client-side: hide tickets whose `Blocked by` lists ≥1 ticket not in `done`.
- **Inline card expansion** (no modal). One card open at a time. Click to toggle, Esc when expanded to close.
- **SSE endpoint** auth-gates to `project.ownerId === session.user.id`. Sends initial `: connected` comment, keepalive comments every 30s. Cleanup via `cancel()` (interval cleared + broadcast unsubscribe).
- **Refetch on event**: client re-hits `/api/projects/[id]/tickets` rather than receiving full payload via SSE. Simpler, source-of-truth pattern.
- **Two-font swap from spec:** `Big Shoulders Display` is not in `next/font/google`'s catalog (neither is the renamed `Big Shoulders`). Substituted **Anton** — condensed, bold, brutalist feel preserved. Atkinson Hyperlegible / Inter / JetBrains Mono unchanged.
- **`@import` font loading caused multi-second cold loads in dev mode.** Replaced with `next/font/google` in the root layout — fonts download at build time, served as local files with proper preload. **Dev mode is still slow regardless** (compile-on-first-hit overhead); production build (`npm run build && npm run start`) loads pages in <100ms.
- **Verified end-to-end:** push fired webhook → smee → handler → DB update → SSE broadcast → open board tab refetched and re-rendered with HV-007 sliding from Backlog → In progress → In review across two demo pushes. Production build serves the board near-instantly.
- **HV-013 filed** for global design-system styling on `/login`, `/dashboard`, `/projects/new` (these stayed plain HTML in HV-007's scope).
