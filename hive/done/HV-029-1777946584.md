## Goal
A single markdown doc — `docs/DEPLOY.md` (or `hive/DEPLOY.md`) — that walks any operator through provisioning Bot Hive on Render (or another host) end-to-end in under 30 minutes.

## Why
The first prod deploy (HV-023 + HV-024) was painful — credentials came from four sources (OAuth App dev, OAuth App prod, GitHub App dev, GitHub App prod), env vars from two places (Render auto-injected vs manual), and several gotchas surfaced mid-flow (NEXT_PUBLIC_APP_URL missing from `render.yaml`, install-callback redirect using `req.url`, GitHub App permissions left empty by default, etc.). A runbook captures the working sequence so the next deploy (staging env, custom domain, second prod, anyone else's clone) is a one-shot.

## Done when
- New file `docs/DEPLOY.md` (or wherever ops docs go) with sections:
  - **Prerequisites** — Render account, GitHub account, `bot-hive` repo, etc.
  - **Step 1: Create the OAuth App** — exact github.com path, fields to fill, where the secret goes
  - **Step 2: Create the GitHub App** — exact path, permissions (Contents R/W, Metadata Read), Push event subscription, callback / setup / webhook URLs
  - **Step 3: Generate and save the GitHub App private key**
  - **Step 4: Install the GitHub App on the target repo with explicit repo access**
  - **Step 5: Provision Render via `render.yaml` blueprint**
  - **Step 6: Render env var checklist** — table of every var, source, where it goes, with screenshots/links
  - **Step 7: First deploy + migration verification**
  - **Step 8: Smoke test (sign-in → install → board)**
  - **Troubleshooting appendix** — every gotcha we hit (CORS from missing NEXT_PUBLIC_APP_URL, install-callback redirect to localhost, GitHub App permissions empty by default, OAuth App's single-callback constraint requiring separate dev/prod apps, etc.)
- The runbook is self-contained — someone unfamiliar with the project can follow it cold.

## Desired output
Future operator setup time: <30 min, no chat-with-Claude needed.

## Success signals
- A second person follows the doc and deploys successfully without questions.
- The doc covers every gotcha that came up in HV-022/023/024.

## Failure signals
- The doc is too generic and the next deploy still hits surprises.
- The doc references obsolete UIs (github.com / Render dashboards change).

## Tests
- Self-test: read it cold, follow it on a throwaway Render account, see if it works.

## Notes

- Out of scope: automating the deploy (Terraform / CDK). Manual runbook is the right level for a single-operator project.
