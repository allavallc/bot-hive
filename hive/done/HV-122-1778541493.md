## Concrete repro

1. Bot A has a historical event log (`hive/events/<colony>.A.log`) with entries from N days ago, plus events within the last 2h (so it's "active").
2. Bootstrap bot B today by writing `.bot-hive-identity` and creating `hive/events/<colony>.B.log` with events only from today.
3. Run `whoami.sh` from B's checkout. Result: B is `coder (2/2)`, A is `PM + tester (1/2)`.
4. Intent was the opposite — B was bootstrapped as the PM.

## Root cause

`scripts/whoami.sh` lines 41-47 walks each event log, takes the first non-comment line's timestamp as `first_ts`, and sorts ascending. Older `first_ts` = higher tier. The heuristic correctly captures "tenure" in a steady-state colony but fails when:

- A bot returns from dormancy (its old `first_ts` survives).
- A new PM is bootstrapped specifically to coordinate (its `first_ts` is today by construction).

## Fix paths (pick in PR)

- **Option A — explicit role declaration in `.bot-hive-identity`.** Add a `role=` line. `whoami.sh` honors it if present; otherwise falls back to the timestamp heuristic. The PM bootstrap writes `role=pm`. This is the cleanest long-term answer.
- **Option B — re-anchor `first_ts` per-session.** Each session writes a "presence" event on bootstrap; `whoami.sh` uses the most recent CONTIGUOUS presence cluster as the session start. Fragile — defines "session" by gap thresholds.
- **Option C — let the human override via CLI flag.** `whoami.sh --role=pm` or `--rank=1`. Makes role assignment explicit but moves complexity to the caller.

Recommend Option A. Explicit > clever heuristic.
