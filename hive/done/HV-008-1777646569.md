## Goal
Add a `Type: story | bug` frontmatter field and render a small bug icon top-left on cards when `Type: bug`.

## Why
Bugs and stories read differently; a glance-level marker speeds triage on the kanban.

## Done when
- Frontmatter accepts `Type: story | bug` (default `story` when missing).
- Parser exposes `type` on the ticket record; stored in `tickets.frontmatter` jsonb (no migration).
- Card UI renders a 16px bug glyph top-left when `type === "bug"`, in `--accent` (`#c4724a`).
- Parser rejects values other than `story | bug`.

## Desired output
Bug-typed cards show a bug icon; story cards render unchanged.

## Success signals
- Existing tickets without `Type` still render as story (backward compatible).
- Icon position holds at narrow widths without overlapping ID, title, or feature-set badge.

## Failure signals
- Default treated as `null` instead of `story`, breaking renders.
- Icon overlaps card chrome on small viewports.

## Tests
- Unit: `Type: bug` → `type === "bug"`.
- Unit: missing `Type` → `type === "story"`.
- Unit: `Type: feature` → parser error.
- Manual: render bug + story side-by-side on the board, eyeball icon position.

## How to test
1. Edit any ticket's frontmatter to add `- **Type**: bug`.
2. Push the change.
3. Within ~10s the corresponding card on the board shows a 14px monoline bug icon (terracotta accent) inline before the HV-id.
4. Remove the field or set `Type: story` → icon disappears.

## Notes
- No schema migration — `type` lives in jsonb until an index is justified.
- Final icon SVG choice deferred to build time; pick a single monochrome glyph, no fill variants.
- Out of scope: bug-specific fields (severity, repro), bug-only filters/views.

## Resolution
- Single file change: `src/app/projects/[id]/board.client.tsx` adds a `<BugIcon />` component (14px monoline SVG — ellipse body + center divider + 2 antennae + 6 legs) rendered conditionally inside `cardTop` when `frontmatter.Type === "bug"`.
- `board.module.css` adds a small `.bugIcon` rule (`color: var(--accent)`, `flex-shrink: 0`).
- **Permissive parsing:** any value other than `"bug"` (including missing, typos, "story") shows no icon. No parser-level validation, no error throw — Bot Hive-style render tolerance, validator concern is separate (HV-002 spec).
- **Position:** inline at the start of `cardTop` row (before HV-id), not absolute top-left. Avoids collision with the in-progress walking-robot mascot which animates around the card border.
- Verification deferred — user has no Type-bug tickets in the test repo. Marked `bot-claimed` per Bot Hive semantics. User can flip to `human-reviewed` after eyeballing one.
