## Goal
Coordination-metadata PRs (ticket moves, AGENTS.md / HIVE.md edits, ticket filings) should land in seconds, not minutes. Source-code PRs continue to pay the full ~2-3 min CI cycle. The PR queue stops compounding into N² CI runs when many bots are working in parallel.

## Why
The PR queue this session has been the dominant friction. Each merge of any PR makes every other open PR `BEHIND`, requiring a re-run of CI to clear. A typical bot session opens 5-10 PRs in flight; with full CI on every one and serial auto-merge, the last PR can wait 20+ minutes purely for CI cycles.

Most of those PRs are coordination metadata — they don't touch source. Running the full lint/typecheck/test/build for a `hive/backlog/` → `hive/in-progress/` move is pure waste. Skipping it eliminates ~2 min per coordination PR.

## Done when

### Two-job structure

`.github/workflows/ci.yml`:

- **`detect` job** (always runs, ~5s): inspects the changed file set vs the merge-base with main. Sets `source_changed=true` if any file outside the coordination-metadata allowlist is touched. The allowlist: `hive/*`, `docs/*`, `tasks/*`, `README.md`, `CLAUDE.md`, `AGENTS.md`, `.gitattributes`. Anything else (`src/`, `tests/`, `migrations/`, `package.json`, `.github/workflows/`, etc.) flips `source_changed` to `true`.
- **`ci` job** (always runs as the required status check; gates internal steps): when `source_changed == 'false'`, runs only a single notice step and exits 0. Postgres service container, `npm ci`, lint, typecheck, test, and build are all `if:`-gated on `source_changed == 'true'`.

### Edge cases
- **Initial push / shallow ref**: when no merge-base sha is available, default to `source_changed=true` (safe — never accidentally skip a real source change).
- **Allowlist conservatism**: the allowlist is deliberately narrow. If unsure whether a file affects source, the workflow runs the heavy CI. False positives are wasted CI minutes; false negatives ship broken code. Allowlist is conservative on purpose.
- **`.github/workflows/` itself is NOT in the allowlist** — workflow changes touch CI behavior and must be tested. Avoids the "I broke CI by editing CI" footgun.

### Verification
- This PR itself touches `.github/workflows/ci.yml` — NOT in the allowlist. Heavy CI runs on this PR. If it passes, the gating logic is at least functional for the source-changed path.
- A future hive-only PR (a ticket move) will exercise the skipped path and should land in ~5-10s.

## Out of scope
- GitHub merge-queue (the canonical fix for the merge-train problem). Bigger change, requires branch protection rule changes. Filed separately if needed.
- Parallelizing test / build across multiple jobs. Could halve CI duration for source PRs, but won't help the coordination-metadata case which is the dominant volume.
- Path-based filtering on the trigger (`paths: / paths-ignore:`). Rejected — would skip the workflow entirely for hive-only PRs, leaving "Required status check expected" forever (branch protection waits on a check name that never appears). The two-job pattern preserves the required-check while skipping the work.

## Notes
- The cost of the `detect` job is ~5s — fast enough that it disappears into the noise. The win is skipping ~2 min on every coordination-metadata PR.
- For multi-bot scenarios this compounds: 10 hive-only PRs that previously each took 2 min now take 10s total. Saves ~20 min of wall time per typical session.
- The pattern is a standard GitHub Actions workaround for "skip required-check when irrelevant" — `ci` job always runs and emits a status, but its steps are conditional on the detect job's output.
