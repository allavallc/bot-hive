## Goal
Eliminate the 2-3 minute window between "bot decides to work HV-X" and "bot's PR moves HV-X out of backlog/" during which a parallel bot can DAG-walk into the same ticket. The platform exposes a tiny claim endpoint that bots call before doing work; it records the claim in a transient DB table with a 30-min TTL and broadcasts SSE so the swarm sees the claim within ~1s.

## Architecture — fence, not authority
The platform's `active_claims` table is **a fence, not the source of truth**. Git remains canonical:

- The fence rejects 409 if a peer is already holding the ticket
- The fence broadcasts SSE so the swarm panel + other bots see the claim immediately
- The bot still does canonical work in a real Git commit (PR moving the ticket file)
- The webhook clears the fence claim when the canonical move lands
- If the bot abandons (no canonical move within 30 min), the claim expires

Wipe `active_claims` tomorrow and the swarm still works — just slower, more git-collision-prone. Coordination state is transient; canonical state is Git.

## What's in this PR

### Schema + migration
- `active_claims` table: composite PK on (project_id, hv_id), expires_at index. Migration `0004_tiresome_wildside.sql`.

### POST endpoint
- `POST /api/projects/[id]/tickets/[hvId]/claim` — body `{ handle }`. Validates HV-id format and handle. Checks for existing unexpired peer claim → 409. Otherwise upserts with 30-min TTL and broadcasts SSE.

### Read endpoint extension
- `GET /api/projects/[id]/events` now includes unexpired claims as `kind: "claim-active"` entries with hvId + expiresAt. The swarm panel renders them; bot DAG-walks filter by them.

### Broadcast
- `BroadcastEvent` extended with a `claim` variant. The SSE stream pipes it through unchanged (existing generic dispatch).

### Webhook hook
- After `initialSync`, the handler queries tickets with `state != backlog` for this project and deletes any matching claims. Also sweeps expired claims opportunistically.

### Swarm panel
- Renders `claim-active` entries with a distinct `◐` glyph + amber color + italic message. Distinguishable from canonical lifecycle events (which render with the existing color-coded glyphs).

### Convention docs
- AGENTS.md "DAG-walk" gains step 5 (filter active claims) + step 7 (reserve via fence first).
- hive/HIVE.md gains a "Soft-fence claims — sub-second collision rejection" subsection explaining the fence-not-authority contract and the canonical-via-Git lifecycle.

## What this PR does NOT do
- Does not enforce that bots use the fence. A bot that skips it can still race a peer (the swarm degrades to old-style git-push-race resolution). The fence is best-effort coordination; canonical correctness still flows through Git.
- Does not touch code-PR semantics. Code review, CI, branch protection — all unchanged.
- Does not introduce a new auth model. Bots authenticate via the user's session cookie (same as the notes endpoint). Cross-actor isolation is not in scope.
- Does not extend the fence to other event types (presence, status, blocked). v1 is claims only — extend later if it becomes useful, per the principle of growing the architectural surface slowly.
