## Goal
Let a signed-in user install Hive on a repo and see its `hive/` folder synced into the DB.

## Why
This is the first end-to-end loop: identity → installation → project row → tickets in DB. Without it the board has nothing to render.

- `/projects/new` shows an "Install Hive on a repo" button linking to the GitHub App install URL.
- `/projects/install/callback` handles `?installation_id=X&setup_action=install`, lists installation repos, for each: detect-or-create `hive/` folder, write a `projects` row, kick off `initialSync(projectId)`, redirect to `/dashboard`.
- `src/lib/sync.ts` exposes `initialSync(projectId)`: recursive tree fetch via Git Trees API, blob-by-blob read, parse, transactional upsert into `tickets`/`features`, sweep deletions for rows not in current tree, set `last_sync_sha` to repo HEAD. Also exposes `ensureHiveFolder(installationId, owner, repo)` that creates a starter `hive/` (subdirs + HIVE.md + config.json) via a single Git Trees commit when missing.
- `src/lib/parse.ts` exposes pure `parseTicket(content)` and `parseFeatureSet(content)` reusing Bot Hive field/section names verbatim.
- `/dashboard` lists the signed-in user's connected projects (replaces "No projects yet" placeholder); each entry links to `/projects/[id]` (404s until HV-007 — expected).
- GitHub App permission bumped to `Contents: Read and Write`.

## Desired output
Install Hive on a fixture repo with 3 backlog + 1 in-progress + 1 feature-set → click Connect → within 30s, rows appear in `tickets`/`features` with `sync_state.last_sha` matching HEAD.

## Success signals
- Re-running `initialSync` is idempotent: same input → same DB state, no duplicate rows.
- Parser tolerates legacy/missing optional fields (matches Bot Hive validator behavior).

## Failure signals
- Partial sync leaves `last_sha` ahead of actual data on transient API failure.
- Frontmatter parse errors crash the whole sync instead of skipping the bad file with a warning.
- Files outside `hive/` end up parsed (path filter wrong).

## Tests
- Manual: connect a fixture repo, inspect rows.
- Unit: `parseTicket` round-trips canonical Bot Hive tickets (use copies from `Bot Hive/done/`).
- Unit: `parseTicket` on a file missing `Desired output`/`Success signals` returns a ticket without those fields, no throw.
- Unit: `initialSync` called twice in a row produces zero diff after the second call.

## Notes
- Initial-sync runs in-band on the install callback; if it grows past a few seconds we move it to a background job — not now.
- Test target is `allavallc/bot-hive` itself (already installed, real ticket corpus). No separate fixture repo needed.
- **Auto-create scope (added beyond original DoD):** Hive scaffolds `hive/` for repos that don't have it yet, on first connect. Removes the "user must run Bot Hive locally first" friction. Single commit with subdirectory `.gitkeep` files + `hive/HIVE.md` + `hive/config.json`. Existing `hive/` folders are not modified.
- Multi-repo install: one `projects` row per repo. Repos without `hive/` get scaffolded (bumping permission to `Contents: Write` for this).
- Per-file parse failure: log warning + skip file, continue sync. Matches Bot Hive's render-tolerant pattern (validator runs separately in CI).
- Out of scope: deletion / disconnect flow.

## Resolution
- 5 files: `src/lib/parse.ts`, `src/lib/sync.ts`, `src/app/projects/new/page.tsx`, `src/app/projects/install/callback/route.ts`, `src/app/dashboard/page.tsx`.
- **Sync strategy:** single `GET /repos/{owner}/{repo}/git/trees/{HEAD}?recursive=1` for all paths, then `GET /repos/{owner}/{repo}/git/blobs/{sha}` per file. Filter to `hive/**.md`. Parse + upsert + sweep-delete-not-in-tree wrapped in one Drizzle transaction so partial API failure rolls back cleanly.
- **Auto-init (`ensureHiveFolder`):** detects `hive/` via Contents API; on 404, creates blobs → tree (with `base_tree` for current state) → commit → branch ref update in one atomic 6-API-call sequence. Files: `hive/HIVE.md` (read from this repo's `hive/HIVE.md` at runtime), `hive/config.json`, `.gitkeep` in each subdirectory. Existing `hive/` is left alone.
- **Multi-repo install:** callback iterates all repos in the installation; per repo: ensure folder + upsert project row + initialSync.
- **Parser:** hand-rolled regex over `# [HV-XXX] Title` heading + `- **Field**: value` bullets + body-as-text. No external markdown lib.
- **GitHub callback gotcha:** when an App is already installed, GitHub doesn't re-invoke the Setup URL — it shows a config page instead. Direct-hit `/projects/install/callback?installation_id=X` bypasses this for re-sync.
- **Verified end-to-end** against `allavallc/bot-hive` at commit `15fdd35`: 1 project (`active`), 11 tickets (4 done + 7 backlog matching repo state), 1 feature set, `last_sync_sha` matches HEAD.
- Idempotency proven structurally: Drizzle `onConflictDoUpdate` + `notInArray` sweep are no-ops for unchanged input.
- Unit tests deferred to HV-010 (Vitest not installed).
