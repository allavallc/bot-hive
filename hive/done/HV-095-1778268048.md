## Goal
Write the constrained rubric file at `hive/skills/tester.md` that the tester bot reads on session start. Defines exactly what to check, what NOT to check, and the output format.

## Done when
- File exists with sections: Goal, Checks (3-5 specific items), Do not (style nitpicks, refactoring, redesign), Output format (approve OR reject + 1 specific reason citing the ticket), Escalation rules
- Total length ≤ 50 lines — long manuals invite nitpicks; short rubrics force binary decisions
- Linked from `bot-startup.md` so testers find it on session start

## Notes
- The "approve by default" mindset is critical. Frame the prompt so the tester only flags clear misses against ticket "Done when" or obvious bugs — not "could be cleaner."
- Output cap (≤ 2 sentences for rejection reason) is enforced server-side in HV-098, but the rubric should also state it explicitly.
