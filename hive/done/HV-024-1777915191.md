## Goal
Wire prod URLs into GitHub on both apps so the deployed Bot Hive can complete sign-in (OAuth App) and receive webhooks (GitHub App).

## Why
After HV-023 the app is reachable at a public URL but GitHub still bounces every OAuth callback to localhost and still posts every webhook to the smee proxy. Until these URLs are updated, prod is effectively unreachable.

## Done when
- **GitHub OAuth App — separate prod app, not appended to the existing one.** OAuth Apps allow only **one** Authorization callback URL (single field, no list), so a multi-environment setup needs separate apps:
  - New OAuth App `Bot Hive (Prod)` registered at github.com → Settings → Developer settings → OAuth Apps → New OAuth App.
  - Homepage: `https://<render-prod-url>`. Authorization callback URL: `https://<render-prod-url>/api/auth/callback/github`. Device Flow off.
  - New `GITHUB_CLIENT_ID` + `GITHUB_CLIENT_SECRET` set in Render env vars (overwriting the dev placeholders set in HV-023).
  - Local `.env` keeps the original (dev) OAuth App credentials. Local-dev sign-in keeps working unchanged.
- **GitHub App — also separate prod app, matching the OAuth App split.** Plan changed mid-ticket: rather than repoint the existing dev app, registered a new `Bot Hive (Prod) - AD` GitHub App so local dev's "Hive (local dev) - AD" keeps its smee config intact:
  - New GitHub App with Homepage / Callback / Setup / Webhook URLs all pointing at the Render prod URL.
  - **Repository permissions**: Contents = Read and write, Metadata = Read-only.
  - **Subscribe to events**: Push.
  - New webhook secret (separate from the dev one — each app signs its own deliveries).
  - New private key generated; pasted into Render's `GITHUB_APP_PRIVATE_KEY` env var.
  - Installed on the bot-hive repo with explicit repo access (initial install was created without permissions and required a follow-up Permissions edit + Accept-new-permissions step before repos could be selected).
- A test push to a connected repo fires the webhook to the prod URL (verify in Render logs).

## Desired output
Sign-in from the prod URL completes the OAuth round-trip. Pushes to a connected repo update the live board on prod.

## Success signals
- Render logs show `POST /api/github/webhook` requests when commits are pushed.
- A sign-in attempt from the prod URL redirects to GitHub, then back to `https://<render>/dashboard`.
- Local dev still works (callback to `localhost:3000` continues to function).

## Failure signals
- `redirect_uri_mismatch` from GitHub on sign-in → callback URL not whitelisted; fix the OAuth App settings.
- Webhook 401s in prod → `GITHUB_APP_WEBHOOK_SECRET` mismatch between Render env and the GitHub App settings.

## Tests
- Manual: sign in from the prod URL, confirm callback succeeds, dashboard loads.
- Manual: push to a connected repo, confirm webhook hits prod and the board updates.
- Manual: sign in from `localhost:3000` (local dev), confirm still works.

## How to test
1. Visit the Render prod URL → click Sign in with GitHub. Expected: redirect to GitHub, authorise the new prod OAuth App, redirect back to `/dashboard` on prod.
2. Push a `hive/` commit to a connected repo. Watch the Render logs — expect `POST /api/github/webhook 200`. Reload `/projects/[id]` in prod, see the board reflect the change.
3. Run `npm run dev` locally, open `localhost:3000`, sign in. Expected: still works (uses the original dev OAuth App credentials in local `.env`).

## Notes
- **Plan changed during execution**: original plan was "two OAuth Apps but one GitHub App" — repointing the dev GitHub App at prod. Pivoted to "two of each" so local-dev webhook flow stays intact via smee. End state is symmetric: dev has its OAuth App + GitHub App, prod has its own pair.
- Each GitHub App generates its own webhook secret (independent values), so dev and prod env files carry different `GITHUB_APP_WEBHOOK_SECRET` values now.
- Out of scope: custom domain, automating dev/prod credential sync.

## Resolution
- **OAuth App "Bot Hive (Prod)"** registered. Authorization callback URL `https://bot-hive-j0ax.onrender.com/api/auth/callback/github`. Client ID + Secret in Render env vars. Sign-in confirmed working on prod.
- **GitHub App "Bot Hive (Prod) - AD"** registered. All four URLs (Homepage / Callback / Setup / Webhook) pointing at prod. Permissions: Contents R/W, Metadata Read. Subscribed to Push events. Installed on bot-hive repo with repo access.
- **Render env vars** set: `BETTER_AUTH_URL`, `NEXT_PUBLIC_APP_URL`, `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY`, `GITHUB_APP_WEBHOOK_SECRET`.
- **render.yaml updated** mid-ticket to document `NEXT_PUBLIC_APP_URL` (was missing — caused CORS errors on sign-in until added).
- **Bug fixed mid-ticket**: install callback redirects used `req.url` which on Render's reverse-proxied setup returns the upstream `localhost:10000` instead of the public origin. Fixed via new `publicUrl(req, path)` helper that reads `BETTER_AUTH_URL` first. Without this fix, completing the GitHub App install on prod redirected users to localhost. Commit `eb9f53f`.
- **Install flow verified end-to-end**: project row created in prod DB, dashboard auto-discovered the project, board page renders with synced tickets. Webhook delivery (Push events from prod's GitHub App → prod's `/api/github/webhook`) — visible in Render logs as `installation` / `installation_repositories` events on initial install (correctly deferred per the webhook handler's Phase-2 stance).
- **Local dev still works**: `.env` retains the original "Bot Hive" OAuth App + "Hive (local dev) - AD" GitHub App credentials. No interference from the prod setup.
