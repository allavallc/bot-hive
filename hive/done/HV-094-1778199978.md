## Goal
Notes are conversational direction, not canonical state — they don't belong in Git. Replace the per-note PR + auto-merge ceremony with a `human_notes` Postgres table + SSE broadcast. Notes appear on the panel within ~1s of Send instead of 2-3 min.

Same primitive as HV-090's claim fence: transient state in DB, not Git. Wipe the table tomorrow and the swarm still works (just loses chat history).

## Architecture
- POST `/api/projects/[id]/notes` — session auth, validates message, INSERT into `human_notes`, broadcasts SSE
- GET `/api/projects/[id]/events` — reads notes from DB instead of `hive/notes-to-bots/*.log`. Lifecycle events still come from Git (canonical state); bot→human notes still come from Git (`hive/notes-to-humans/*.log` — bots have git auth but no API session)

## Asymmetry — by design
- Human → bot: DB + SSE (instant)
- Bot → human: still Git (existing path; bots have git auth, no API session)
- Acceptable for v1; if bot→human note frequency becomes friction, build bot API auth later.

## Panel cleanup (also in this PR)
- Dropped action-specific glyphs (→, ✓, ⊘, etc.) — the action word is right there in the row text
- Replaced with a single colored bullet `●` per row, color from `robotColor(actor)`
- Each bot/human keeps a consistent color across activity AND notes — easy identification at a glance
- Dropped per-action glyph CSS, dropped `note-to-bots` / `note-to-humans` direction styling (color does the work)
