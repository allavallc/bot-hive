## Goal
A single reusable module that resolves "does user X have access to repo Y on GitHub?" using the user's OAuth token, cached for 5 minutes per user.

## Why
Five auth-check sites currently each query `projects.ownerId`. After FST-003, every check is "is this user a GitHub collaborator on repo Y?". One module, five callsites consuming it — caching, errors, Octokit plumbing centralised. Direct reuse.

## Done when
- New file `src/lib/access.ts` exporting:
  - `listUserRepos(userId): Promise<string[]>` — returns `["owner/name", …]` from `octokit.repos.listForAuthenticatedUser({ visibility: 'all', affiliation: 'owner,collaborator,organization_member', per_page: 100 })` with pagination.
  - `userHasRepoAccess(userId, githubRepo): Promise<boolean>` — `(await listUserRepos(userId)).includes(githubRepo)`.
  - `invalidateUserCache(userId): void` — called from sign-out.
- 5-minute in-memory LRU cache, capped at 1000 entries.
- Reads OAuth token from `account` where `providerId = 'github'`.
- 401 from GitHub clears the cache entry and returns `false` (graceful).

## Desired output
A clean helper. Importers don't think about caching, OAuth tokens, or pagination.

## Success signals
- Cache-warm calls return in <5ms.
- API rate-limit usage stays well under 5000/hr/user.

## Failure signals
- LRU cap missed → memory leak.
- Cache lag up to 5 min after access changes (acceptable per spec).
- Token rotation → next call returns 401, cache clears.

## Tests
Vitest, mocked Octokit:
- Cache hit returns without re-querying.
- Cache miss queries, populates, returns.
- 5-min expiry triggers re-query.
- 401 clears cache, returns `false`.
- User without OAuth token returns `[]` / `false`.
- Pagination: 250 repos returned across 3 pages.
- LRU eviction at cap.

## Notes
- Single-process Map. Distributed cache (Redis) is FST-005's problem if/when we go multi-instance.
- Out of scope: webhook-driven invalidation on GitHub permission change.
- Helper does not touch `projects` table — joining the access list with project rows happens at callsites (HV-019).
- Sign-out cache invalidation hooks via `src/lib/sign-out.ts` calling `invalidateUserCache` (avoids touching Better Auth internals).
