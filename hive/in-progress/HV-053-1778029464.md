## Goal
On the in-review ticket panel (HV-046's UI), the **Accept** and **Reject** buttons stay pinned at the top of the panel (or in a sticky header) so they remain visible as the user scrolls through long ticket bodies. Today the buttons sit at the bottom of the panel and scroll away with the content — for a long ticket body, the user has to scroll back to the top to act.

## Why
Tickets in Bot Hive vary wildly in length — short bug reports and 200-line ADR-style spec tickets both flow through the same review surface. With the action buttons at the bottom, reading + acting becomes a two-step UX: scroll down to read, scroll back up to click. A sticky header puts the buttons within thumb's reach the entire time.

This is a small UX fix but it's the difference between "review feels heavy" and "review is one click."

## Done when

- The right-side panel from HV-039 / HV-046 has a header bar at the top that includes:
  - Ticket ID + title (left side)
  - **Accept** and **Reject** buttons (right side)
  - Close (×) button at the far right
- The header is `position: sticky` (or fixed within the panel scroll context) so it remains visible as the body scrolls.
- Visual: the header has a subtle background or border separating it from the scrollable body.
- All existing accept/reject behavior from HV-046 is preserved — only the position changes.
- typecheck + lint + tests + build all clean.

## Desired output
A user opens an in-review ticket. The Accept / Reject buttons are visible the moment the panel opens. The user reads as much body as they want — buttons stay put. One click resolves the review. No scrolling-up gymnastics.

## Success signals
- The UX feels lighter on long tickets (subjective; a ticket with 200+ lines of body should feel about the same to review as a 20-line one).
- No layout regressions on short tickets (the sticky header doesn't add wasted space).
- Mobile layout (if applicable) keeps the same pattern.

## Failure signals
- Sticky header eats too much vertical space, especially on small screens.
- Button styles drift between sticky and non-sticky states.
- Confirmation dialog from HV-046 still works — buttons still trigger the modal.

## Tests
- Manual: open a long ticket (e.g., HV-031 itself, which has 200+ lines). Scroll to the bottom. Confirm the Accept/Reject buttons are still visible at the top.
- Manual: open a short ticket. Confirm no visual regression — header looks normal.
- Manual: click Accept; confirm the existing flow (confirmation, PR creation, etc.) still works.
- Manual: same for Reject.
