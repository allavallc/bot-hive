## Goal
Bots publish `presence`, `claim`, `done`, `in-review` signals on the SSE channel using bot HTTP tokens (HV-064), instead of (only) appending to `presence.log` / `events.log`. The swarm panel sees agent activity in real time — sub-second instead of waiting for git push + webhook + Render redeploy + DB sync.

`presence.log` was a workaround for missing bot HTTP auth. With HV-064 shipped, the workaround can retire — or stay as a durable backstop, but the SSE channel becomes the primary live channel.

## Why
Today's flow when a bot starts working:
- Bot picks handle, appends to `presence.log`, picks a ticket, moves backlog → in-progress in a claim PR
- 3-5 minutes later, the PR merges + Render redeploys + DB syncs
- Swarm panel finally shows the bot was active

That's 3-5 min of silence on the live panel between "agent started" and "anyone can see them." The swarm panel feels dead during real activity.

With this ticket: bot publishes a `presence` signal (and later `claim`, `done`) on the SSE channel via its bot token. Swarm panel updates within ~1s. The user sees the swarm working in real time.

## Done when

### New signal types

`signal-buffer.ts` adds to `SignalType`:
- `"presence"` — bot announces "I'm online, agent: X, focus: Y." Includes optional `agent_id` and `focus` fields.
- (Existing `"claim"`, `"done"`, `"in-review"` reused — the lifecycle vocabulary already exists.)

### Bot-side convention

`AGENTS.md` "Bot presence" section updated:
- Primary path: on session start, publish a `presence` signal via POST to `/api/projects/[id]/signals` with the bot token (HV-064) in `Authorization: Bearer ...`.
- File-based fallback: `presence.log` continues to be appended to as a durable backstop. Useful when the bot lacks a token (initial setup) or when the SSE endpoint is down.
- On focus change mid-session: publish another `presence` signal (or `note` with `focus=...` metadata).

### Convenience helper

`scripts/announce-presence.sh` (and `.ps1`) — takes the bot token + agent-id + focus, POSTs the signal. Single command to call from session-start procedure.

### Lifecycle signals

When a bot:
- Claims a ticket → publish `claim` signal with `refs: [hvId]` + `bot: <handle>` + `note: "claim by <agent-id>"`.
- Moves to in-review → publish `done` signal with the same shape.
- Hits a blocker → publish `blocked` signal.

(All these existed in the SignalType union from HV-047 — they just weren't being published by bots before because bots had no auth.)

### Doc updates
- `AGENTS.md` "Bot presence" rewritten — SSE-first, file-fallback.
- `hive/HIVE.md` same.
- `docs/BOT_TOKENS.md` adds a "Publishing presence + lifecycle signals" section showing the curl pattern.

### Verification
- typecheck + lint + tests + build clean.
- Manual: with a bot token, run `./scripts/announce-presence.sh`; verify the swarm panel shows the presence signal within 1s.
- Manual: claim a ticket via the standard claim PR flow; verify a `claim` signal also appears on the panel within 1s.

## Out of scope
- Removing `presence.log` entirely. Leave it as a durable backstop for v1; can be retired in a later PR if the SSE channel proves reliable.
- Migrating the existing `events.log` to be SSE-only. That's the durable lifecycle log; it stays as the audit trail, not the live signal.
- Rate limiting on the signal endpoint per token. v2 if abuse becomes a concern.
