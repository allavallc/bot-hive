## Goal
Clicking a ticket card on the board opens its full content in a modal overlay (with backdrop, close button, Escape-to-close), instead of expanding inline within the column. The card itself stays in place; only the modal appears over the board.

## Why
Today, clicking a card toggles `expanded={true}` and renders the full ticket body in a `<pre>` inside the same `<article>`. Long bodies push every card below it further down the column — to see what's next you have to scroll past the entire ticket, then collapse it again to recover layout. That's hostile to the "scan the board" use case and makes multi-ticket review (read three tickets in a column) painful.

Modals are the standard pattern for "open a card on a kanban" — Trello, Linear, GitHub Projects, Jira all use one. The card stays put; the detail floats above. User can close, scan another, open another — without ever scrolling the board.

## Done when

### Modal behavior

- Clicking any ticket card opens a modal overlay showing:
  - Ticket title (`# [HV-XXX] Title`)
  - All frontmatter fields (Status, Priority, Effort, Feature set, Assigned to, etc.) as a labeled list
  - Full ticket body (the markdown content below the frontmatter)
- The card the user clicked stays visible behind the modal (modal is overlay, not full-page navigation).
- A visible close affordance: an "X" button in the top-right of the modal, AND a "Close" button at the bottom (or just one of these — design choice).
- **Escape key** closes the modal.
- **Clicking the backdrop** (outside the modal) closes the modal.
- **Body scrolling is locked** while the modal is open — the user scrolls *inside* the modal, not the board behind it.
- Modal is **keyboard-navigable**: Tab cycles through interactive elements *inside* the modal (focus trap), doesn't escape into the board behind.
- Focus moves to the modal on open (typically to the close button), and **returns to the originally clicked card on close** (so keyboard users don't lose their place).

### Live-update behavior

- If a ticket is open in the modal and gets updated via the SSE refresh (webhook from a `git push`), the modal content updates in place without closing.
- If a ticket is open in the modal and gets *deleted* / moved to a different state by an external event, the modal stays open with a small banner ("This ticket moved to Done") and the user closes manually. (Don't auto-close on state change — disorienting.)

### Accessibility

- The modal renders with `role="dialog"`, `aria-modal="true"`, `aria-labelledby={titleId}`.
- Native HTML `<dialog>` element is the recommended path — it has built-in focus trap, Escape handling, and is supported in all major browsers as of 2023. (Falls back to a portal-based custom modal only if `<dialog>` proves limiting.)
- Color contrast on the modal background and text meets WCAG AA.

### Implementation hints

- Refactor `Card` in `src/app/projects/[id]/board.client.tsx`: remove the inline `expanded`-state body rendering; replace with a click handler that sets a board-level `openTicketId` state.
- Add a `<TicketModal ticket={openTicket} onClose={...} />` rendered at the board level (probably as a sibling of the columns).
- Use the native `<dialog>` element via a ref + `dialog.showModal()` / `dialog.close()`.
- Backdrop click: handle the `dialog`'s built-in `click` event — if `event.target === dialogRef.current` (the click hit the backdrop, not the dialog content), call close.
- Body scroll lock: the native `<dialog showModal()>` already locks scroll. Free.

## Desired output
A user lands on the board, clicks a ticket, reads its details in a centered modal, closes with Escape, clicks another ticket. Their column position doesn't shift between clicks. They can review 5 tickets in 30 seconds without ever scrolling the page.

## Success signals
- Clicking 5 tickets in a row never causes the column layout to shift.
- The modal opens fast (<100ms perceived).
- Escape works from anywhere inside the modal.
- Backdrop click works.
- Keyboard-only navigation feels natural — Tab cycles within modal, Shift+Tab same, focus returns on close.
- An SSE refresh while a modal is open updates the modal in place (test by pushing a `hive/` commit while the ticket file is open in the modal).

## Failure signals
- Layout shift when a card is opened (means the inline expansion code didn't fully get replaced).
- Tab escapes the modal (focus trap broken).
- Body scrolls behind the modal (scroll lock broken).
- Modal scroll position resets when the SSE refresh hits (bad — should preserve scroll within the modal).
- A11y warnings (axe/Lighthouse) on the modal: missing aria attributes, color contrast.

## Tests
- Manual: open a card in each column. Confirm modal renders with full content.
- Manual: Escape closes. Backdrop click closes. X/Close button closes. Each method preserves layout.
- Manual: open a long ticket (e.g., HV-031). Scroll inside the modal — body behind doesn't scroll.
- Manual: open a ticket on prod, push a `hive/` commit modifying the same ticket, watch the modal content update without closing.
- Manual: Tab through the modal — focus stays inside, doesn't reach the board.
- Manual: Lighthouse a11y check passes.

## Notes
- Out of scope: editing tickets via the modal. This ticket is read-only display in a modal; in-modal editing is a separate ticket.
- Out of scope: linking to a specific ticket via URL (e.g., `/projects/[id]/tickets/HV-039` opens with that modal pre-open). Worth doing later as a separate ticket; deep-link-to-modal is a real UX win for sharing tickets, but out of scope here.
- Out of scope: animation transitions (slide-in, fade, etc.). Plain show/hide is fine for v1; refine later if it feels janky.
- The "clicked card stays in place behind the modal" design intentionally rejects "scroll-to-clicked-card" or "highlight clicked card." The card was already visible (the user clicked it) — leave it alone.
