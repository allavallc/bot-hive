## Goal
Make HV-074's promise practical. The agent-id convention says "on session start, grep for `Assigned to: <your-agent-id>` to find tickets you left mid-flight." That works as a manual command but every agent has to remember the exact incantation. Ship it as a one-line script: `./scripts/my-work.sh` prints the tickets owned by this clone's agent-id.

## Why
Without a helper, agents either copy-paste a grep from the docs (error-prone) or skip the resume step entirely (defeats the convention). With one command, every session starts with "what's mine?" answered in <1 second.

## Done when
- `scripts/my-work.sh` (POSIX) and `scripts/my-work.ps1` (Windows) accept an optional `--agent <id>` flag, otherwise resolve agent-id from `git config bot-hive.agent-id` then default-derive `email@hostname`.
- Each script prints one line per matching ticket: `[<state>] <hv-id> — <title>` for tickets in `hive/in-progress/` and `hive/in-review/`.
- Smoke test: setting `git config bot-hive.agent-id allavallc-cc1` against this clone returns the expected tickets.
- Verified at end of session: `./scripts/my-work.sh` returns clean output.

## Out of scope
- Updating AGENTS.md / HIVE.md to reference the script. Done in a follow-up doc PR after HV-074 lands (avoids hot-file conflicts on those files in this PR).
- Archive view (tickets in done/ owned by me). Not useful for resume; if needed later, a separate flag.
- Slack / chat output formatting. Plain stdout only.

## Notes
- Resolution order matches HV-074's spec exactly. The default-derive (`email@hostname`) covers the no-config case.
- The grep pattern matches `Assigned to: <agent-id>` followed by space, `(`, or end of line — handles both `Assigned to: allavallc-cc1` and `Assigned to: allavallc-cc1 (claude-opus-4-7)`.
- The PowerShell variant uses regex against the file's full content for cleaner matching across line breaks.
