## Goal
Every agent session, on start, appends one line to a new `hive/presence.log` announcing handle, model, and current focus. Mid-session focus changes append another line. Other agents tail this file and learn who's currently online before claiming work.

## Why
Today the swarm has two coordination channels — `hive/events.log` (durable lifecycle) and the SSE signal stream (real-time conversation). Neither carries **presence**: "kestrel just started a session and is about to claim something on FS-005."

The gap shows up at every parallel-bot start: nectar is already mid-session when kestrel boots up, but kestrel has no way to see nectar is active until nectar happens to commit something. If both bots start within a minute of each other and both run DAG-walk, neither knows the other is even there. Presence closes that gap.

events.log is the wrong home — its contract is "durable state transitions of tickets," and presence isn't a state transition; it's chatter about who's at the keyboard. The SSE signal stream is the right semantic home, but bots don't have web-app session auth today (they push via git, not HTTP). A separate `hive/presence.log` file is the right answer for now: same git-sync substrate as events.log, no auth needed, ephemeral by convention (entries older than 24h are pruned on session start).

## Done when

### Convention

`AGENTS.md` and `hive/HIVE.md` gain a "Bot presence" subsection under the real-time channel rules:

- **On session start** (after handle pick, after `focus.md` read, after tailing `events.log`): append one line to `hive/presence.log`:
  ```
  <ISO timestamp> <handle> online model=<model-id> focus=<focus-id-or-empty>
  ```
  e.g.: `2026-05-06T03:30:00Z nectar online model=claude-opus-4-7 focus=feature-set-007-parallel-bot-coordination`
- **On focus change mid-session** (user moves you to a different FS): append another line with the new focus.
- **On graceful session end** (rare — usually sessions just stop without an end signal): append `<ISO> <handle> offline`. Optional; missing is fine.
- The presence line is committed + pushed as part of the next commit the bot makes (the first claim, doc edit, etc.). If the bot has been online >5 minutes without any other commit, push a tiny "presence ping" PR carrying just the presence-line update. This is rare and acceptable overhead.

### File format

`hive/presence.log` is append-only by convention. Header comment lines start with `#`:

```
# Append-only presence log. Each line: <ISO timestamp> <handle> <event> [key=value ...]
# event ∈ {online, focus, offline}. Entries older than 24h may be pruned by any agent on session start.
2026-05-06T03:30:00Z nectar online model=claude-opus-4-7 focus=feature-set-007-parallel-bot-coordination
2026-05-06T03:32:00Z kestrel online model=claude-opus-4-6 focus=feature-set-005-production-deploy
```

### Tail-on-start behavior

When an agent reads `hive/presence.log` on session start, it filters to entries from the last 1 hour and surfaces them in the "I see these other agents online" summary. Stale entries (>1h) are ignored for presence purposes; entries older than 24h may be deleted from the file (FIFO prune) by any agent on session start to keep the file small.

### Future link to the SSE channel

Once project-scoped bot tokens exist (separate ticket — to be filed when bot HTTP auth becomes a real requirement), bots will *also* publish a `note`-type signal on the SSE channel for sub-second presence visibility on the live board. For today, the file-based presence is sufficient.

## Out of scope
- A "who's online" UI panel. The swarm panel will eventually surface presence via the SSE channel; today, it's visible to humans via tailing `hive/presence.log`.
- Heartbeat / liveness checking. Presence is "I just announced myself"; staleness is a separate concept (the existing 2-hour `Last touched` rule on in-progress tickets covers stale-claim recovery).
- Per-handle online indicators on cards. HV-056 is the closer ticket for that.
- Bot HTTP auth (project tokens). To be filed separately when the SSE channel publish path needs it.

## Failure modes
- Bots forget to write the presence line. Mitigation: convention is documented in AGENTS.md + HIVE.md and read on session start.
- Two bots write presence lines simultaneously and collide on the next push. Mitigation: tiny single-file commits rebase trivially; loser pulls and re-pushes.
- File grows unbounded if no agent prunes. Mitigation: opportunistic prune in the session-start procedure.
