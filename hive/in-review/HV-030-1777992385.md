## Goal
The "You've been signed out of Bot Hive..." hint on `/` shows only immediately after a sign-out event, not to first-time visitors who have never signed in.

## Why
Today the hint shows on every visit to `/` until the user clicks "Got it" (a `localStorage` flag). On a brand-new browser/laptop, a first-time visitor sees a confusing message about being signed out — when they have never been signed in. The `localStorage` flag was conflating "dismissed" with "actually signed out" — two different signals. HV-027's resolution flagged this as a follow-up polish ticket; this is that ticket.

## Done when
- `src/lib/sign-out.ts` redirects to `/?signedOut=1` (was `/`).
- `src/app/page.tsx` (server) reads `searchParams.signedOut` and passes a `signedOut: boolean` prop to `<Hero />`.
- `src/app/hero.client.tsx` shows the hint only when the prop is `true`. No `localStorage` read.
- The dismiss button strips the param via `history.replaceState(null, "", "/")` and hides the hint via local state.
- The `bot-hive:signout-hint-dismissed` `localStorage` constant + read/write code is removed entirely.
- A fresh browser visiting `/` directly never sees the hint.
- A user who signs out lands on `/?signedOut=1` and sees the hint.

## Desired output
First-time visitor sees a clean homepage with no confusing message. Just-signed-out user sees the hint, can dismiss, and a reload of `/` shows nothing.

## Success signals
- Open `/` in a private/incognito window → no hint.
- Sign in → sign out → land on `/?signedOut=1` → hint visible.
- Click "Got it" → URL becomes `/`, hint disappears.
- Reload `/` → no hint (param is stripped).
- Sign out twice in a row → hint shows both times (the old `localStorage` version silently broke this).

## Failure signals
- Hint appears on `/` for a fresh visitor.
- Hint persists after dismiss + reload.
- Hint fails to appear after a sign-out.

## How to test
1. Open `/` in a private/incognito window. Confirm no hint is visible.
2. Click "Sign in with GitHub" → complete OAuth → arrive at `/dashboard`.
3. Click "Sign out" in the nav. Confirm you land on `/?signedOut=1` and the hint is visible.
4. Click "Got it". URL should become `/` and the hint should disappear.
5. Reload `/`. Confirm no hint.
6. Repeat steps 2–3. Hint should appear again (the old version would silently fail this case).

## Notes
- This is the long-term, structural fix — the `localStorage` flag was conflating "dismissed" with "signed out". The URL-param model passes the actual sign-out signal from server (the redirect) to client (the hero), stateless and idiomatic.
- Extensible: if future events need similar one-shot hints (session expired, kicked due to inactivity, etc.), the param becomes an enum (`?signout=manual` vs `?signout=expired`).
- No migration needed for the stale `localStorage` key — it is harmless leftover data and will eventually be evicted.

## Resolution
- `src/lib/sign-out.ts` redirect target changed from `/` to `/?signedOut=1`. The query param is the signal that a sign-out just happened.
- `src/app/page.tsx` now accepts `searchParams: Promise<{ signedOut?: string }>` (Next 15 async params), reads `params.signedOut === "1"`, and passes a `signedOut: boolean` prop to `<Hero />`.
- `src/app/hero.client.tsx` now takes a `signedOut?: boolean` prop. The hint's visibility is initialized from the prop (no `useEffect`, no `localStorage` read). Dismiss strips the param via `window.history.replaceState(null, "", "/")` and clears local state. The `DISMISS_KEY` constant and all `localStorage` code are removed.
- Verification: `npm run typecheck`, `npm run lint`, `npm run test` (20/20 pass), and `npm run build` all clean. 17 routes still compile; `/` is dynamic as before.
- Architectural note: the `localStorage` flag was conflating "dismissed" with "signed out" — two different signals. The new model passes the actual sign-out signal from server (the redirect) to client (the prop), is stateless, and supports the same user signing out twice in a row (which the old version silently broke).
