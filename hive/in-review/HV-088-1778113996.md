## Goal
First built version of FS-015 (human ↔ bot communication on the platform). Adds a symmetric per-actor notes channel — humans direct bots from the swarm panel, bots reply to humans through the same panel.

## Architecture
Two parallel directories, both per-actor TSV:

- `hive/notes-to-bots/<human-actor>.log` — written via `POST /api/projects/[id]/notes`, App-committed by the platform
- `hive/notes-to-humans/<bot-actor>.log` — written by bots via direct git push, same way they write their event logs

Format: `<ISO timestamp>\t<message>` per line. Actor is implicit from the filename. Targeting is convention — `@<agent-id>` or `@swarm` in the message body, not a separate column.

Read endpoint (`GET /api/projects/[id]/events`) merges three substrates into a single newest-first stream:
1. `hive/events/*.log` (lifecycle, structured)
2. `hive/notes-to-bots/*.log` (human → bot, prose)
3. `hive/notes-to-humans/*.log` (bot → human, prose)

Each entry is tagged with its `kind` so the panel renders by type.

## What it isn't (v1 explicit non-goals)
- Multi-line messages — file a ticket for paragraph-length direction
- Bot acknowledgment threading — bots may optionally reply but no UI threading; humans see "<bot> last active <N>m ago" as the implicit liveness signal
- Real-time bot interrupt — bots see notes at session boundaries (or via SSE if active). Honest delivery model.
- External chat (Slack, Telegram) — platform-only
