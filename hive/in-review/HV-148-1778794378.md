## Goal

Show server-backed bot live events in the swarm panel without waiting for git-backed event logs.

## Why

The human needs visibility into questions, handoffs, blockers, and review requests as they happen. Once bots can POST live events, the board should render them alongside existing notes and lifecycle events.

## Done when

- Project event APIs include recent `bot_events` rows in chronological output.
- The swarm panel renders bot live events with actor, kind, target, timestamp, and message.
- New SSE `bot-event` broadcasts trigger a panel refresh or inline append.
- Human-to-bot notes and existing git-backed events still render unchanged.

## Desired output

The board shows live bot coordination in near real time.

## Success signals

- A bot POST appears in the panel without a git commit.
- Users can distinguish questions, blockers, handoffs, and status messages.

## Failure signals

- Live events appear only after full project sync.
- Bot events are visually indistinguishable from durable lifecycle events.

## Tests

- Unit/component tests for event mapping if existing panel tests support it.
- Manual board test with a POSTed bot event.

## How to test

- Start the dev server, open a project board, POST a bot event, and confirm the swarm panel updates.

## Notes

Keep the first UI pass plain and dense. This is operational telemetry, not chat polish.
