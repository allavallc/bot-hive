## Goal
Ship the multi-bot foundation in one PR:

1. **"Add a bot" green button** on the project board (right side, fixed position)
2. **Modal** with: next-free handle (server-picked), platform-detected copy-paste line that creates a git worktree + opens a new terminal with Claude Code, list of currently active bots, disclaimer about subscription/credit consumption
3. **Worktree convention**: `./worktrees/<handle>/` subdirectory, `.gitignore` line. Each bot in its own worktree = filesystem isolation, no shared-directory conflicts.
4. **Turn counter**: `**Turns**: <n>` ticket frontmatter field, incremented in `rejectTicket()`, displayed as a small badge on the card (yellow if > 0, red if > 3) — surfaces stuck loops
5. **HV-090 rip-out**: deletes `active_claims` table, `POST /api/projects/[id]/tickets/[hvId]/claim` route, webhook clear-claims logic, events route claim-active query, panel claim-active rendering, broadcast `claim` event variant. Open-PR-as-claim-signal + per-actor file lock + worktree isolation cover the same ground with less code.

Also files **FS-019: Add Tester into the mix** + 5 skeleton tickets (HV-095..HV-099) as backlog for the next phase: tester rubric, role detection, 2-rejection escalation, reason length cap, PM role.

## Architecture decisions

- **Subdirectory worktrees, not sibling**: `./worktrees/<handle>/` keeps the project self-contained. One `.gitignore` line works for every customer.
- **Auto-detect platform in the modal**: Windows (Windows Terminal), macOS (Terminal), Linux fallback. User can override via dropdown.
- **One copy-paste line, not a script**: lower friction than installing a CLI; works without any setup.
- **Turn counter on reject only**: not on every state transition. Counts iterations, not motion.
