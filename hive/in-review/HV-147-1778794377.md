## Goal

Give terminal agents a server-backed way to report live coordination events without writing repo files.

## Why

Bot Hive needs realtime questions, blockers, handoffs, and review signals to move through the server. GitHub remains the durable artifact layer, but live coordination needs lower latency than commits and webhooks.

## Done when

- A `bot_events` table stores bot-originated live events scoped to a project.
- A `POST /api/bots/events` route accepts a connected bot's event, validates it, stores it, and broadcasts it.
- Targeted events can be delivered to open bot SSE streams when the target bot or role is currently connected.
- Event validation rejects missing actor identity, invalid event kind, empty messages, and oversized payloads.
- Tests cover validation, sanitization, and payload-size limits.

## Desired output

Agents can POST a question, blocker, handoff, review request, or status event and have Bot Hive record and push it immediately.

## Success signals

- Live bot events can be added without creating git commits.
- Board and bot stream layers can consume the same stored event shape.
- Future tickets can render these events without changing the POST contract.

## Failure signals

- Bots continue writing transient questions/handoffs to Git because the API is missing required event types.
- Invalid or huge payloads are accepted and pollute live state.
- Targeted events store successfully but never reach connected bots.

## Tests

- Unit tests for accepted event kinds and message cleanup.
- Unit tests for invalid actor, invalid kind, empty message, and oversized data.
- Typecheck to confirm schema, route, and stream event types agree.

## How to test

- Run `npm run test -- src/lib/bot-events.test.ts`.
- Run `npm run typecheck`.

## Notes

Out of scope: board UI rendering, merge enforcement, auth tokens for bot-originated API calls, cross-instance fanout for non-role live events. This ticket uses the current open bot endpoint posture and existing in-process stream registry.
