## Goal
Two passages in `hive/HIVE.md` invoke Claude Code's "skill" abstraction by name:

- Line 109: "**invoke the `product-manager` skill** (installed at `~/.claude/skills/product-manager/SKILL.md`...)"
- Line 651: "**Bot-tester entry point: the `acceptance-tester` skill** (installed at `~/.claude/skills/acceptance-tester/`...)"

Skills are a Claude Code concept. Other agents have their own equivalents (Codex slash-commands, Aider's macros, project-specific scripts, even just markdown checklists). Rewrite these passages so the *purpose* (a host-specific helper that walks the agent through the protocol) is described format-neutrally, with Claude's skill paths moved to a "Reference implementations" footnote / section.

## Why
A non-Claude agent reading "invoke the `product-manager` skill" has no analogue to invoke. The format spec should describe the role ("a helper that drafts the full ticket") and let each agent map that role to its own tooling. The Claude `skills/...` paths are still useful as a concrete reference for adopters of Claude Code.

## Done when
- Line 109's passage reads in agent-neutral terms — describes the role (full ticket draft, principles to follow if the agent has no helper), with the `~/.claude/skills/...` path reframed as "the Bot Hive reference for Claude Code is `~/.claude/skills/product-manager/SKILL.md`; other agents may use their own equivalent or follow the principles below directly."
- Line 651's `acceptance-tester` passage reframed similarly.
- Both passages keep the "follow the principles below" fallback so an agent without any helper still works the protocol correctly.
