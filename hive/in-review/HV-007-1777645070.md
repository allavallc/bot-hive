## Goal
Render the kanban for a connected project and refresh it live from the webhook pipeline via SSE.

## Why
This is the deliverable a user sees. Phases 1.1–1.6 are infrastructure; 1.7 is the product.

## Done when
- `/projects/[id]` is a server component that reads tickets from DB and renders the kanban.
- `board.client.tsx` subscribes to `/api/projects/[id]/stream`; on event, refreshes the board state.
- `/api/projects/[id]/stream` is the SSE endpoint; auth-gated to the project owner.
- `src/lib/broadcast.ts` is an in-memory pub/sub keyed by project; `webhook.ts` calls `broadcast(projectId)` after upsert.
- 5-column grid (`backlog`, `in-progress`, `in-review`, `done`, `blocked`) plus toggleable 6th (`not-doing`).
- Filter bar: priority, effort, feature set, "Ready only" — same semantics as bot-horde's `board.html`.
- Cards expand on click to show full ticket body (Goal, Why, Done when, Desired output, Success signals, Failure signals, Tests, Notes).
- Visual matches `plan/style-guide.md`: dark theme, accent `#c4724a`, Big Shoulders Display + Atkinson Hyperlegible + Inter + JetBrains Mono, square borders, hairline rules, mono small-caps labels.

## Desired output
Push a commit that moves a ticket → card slides to the new column within ~5s without manual refresh. Filters narrow the view immediately.

## Success signals
- SSE reconnects after `next dev` HMR or a network blip without a page reload.
- "Ready only" hides tickets whose `Blocked by` references an unfinished blocker.
- Card detail is keyboard-accessible (Enter/Esc to expand/close).

## Failure signals
- SSE leak: closed clients aren't removed from the pub/sub Set, memory grows unbounded.
- Server component caches stale data; first paint is older than the latest webhook.
- Filter state is lost on board refresh.

## Tests
- Manual (acceptance loop, `User-facing: yes`): push add/move/delete on the fixture repo and watch the board.
- Manual: open two tabs, push once, both update.
- Manual: kill the dev server, restart, board still reconnects.
- Manual: visual diff against bot-horde's `board.html` reference.

## Notes
- In-memory pub/sub is fine for single-process local dev. Production multi-instance broadcast is Phase 2.
- Polling fallback is **not** added now — SSE reconnect handles transient drops.
- The board is the renderer. Once this ships, the `bot-horde` `build.sh` / `validate.py` static-board path is permanently retired for Bot Hive's own dogfood.
