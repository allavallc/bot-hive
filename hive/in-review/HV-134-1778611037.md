## Goal

Bring every operational doc in line with the new identity substrate so a new operator (or a new bot picking up FS-028) can run the system from the docs alone.

## Concrete changes

- **`hive/bot-startup.md`** — rewrite steps 1–4:
  - Step 1: replace `./scripts/whoami.sh` with "call `POST /api/bots/join`" (delegated to the rewritten `whoami` script from HV-133).
  - Step 2 (new): launch the background heartbeat via `nohup ./scripts/heartbeat.sh &` (POSIX) or `Start-Job -FilePath ./scripts/heartbeat.ps1` (PowerShell). Save PID to `.bot-hive-heartbeat.pid`.
  - Step 3: read the skill files returned by `/join`.
  - Step 4 (announce): updated wording: `I'm <colony>.<handle>, seat <n> of <total>, role: <role>, ready.`
  - Step 5 (consume marker, stop): unchanged.
- **`hive/bot-shutdown.md`** — new file. Procedure:
  1. Stop the background heartbeat process (`kill $(cat .bot-hive-heartbeat.pid)` / `Stop-Job`).
  2. `POST /api/bots/leave` with own `{repo_full_name, colony, handle}`.
  3. On 200: delete `.bot-hive-role-cache` and `.bot-hive-heartbeat.pid`.
  4. Print verbatim: `Signed off. Safe to close this window.`
  5. If `/leave` fails, surface the error and do NOT print the safe-to-close line.
- **`hive/seats.md`** — new file. The "how it works" explainer for operators + bots: the seat sheet model, sign-off phrases, heartbeat behavior, what survivors see when someone leaves, troubleshooting (server down, dead seat, double-claimed handle, project not registered). Audience-friendly; links to `docs/2026-05-12-bot-seat-assignment-design.md` for schema + endpoint contract details and to `docs/architecture.md` for stack reference.
- **`AGENTS.md`** — add the sign-off phrase list alongside the kickoff phrase section: canonical `stop your hive work`, aliases `sign off`, `leave the hive`. Bots are instructed to recognize any of these as the shutdown trigger the same way `start the hive` is recognized today.
- **`hive/HIVE.md`** — replace the two out-of-scope bullets per the spec's "HIVE.md revision" section. Narrow the text so identity/seat is explicitly carved out from "no scheduler / no heartbeat."
- **`.gitignore`** — add `.bot-hive-role-cache` and `.bot-hive-heartbeat.pid` (worktree-local, per-session).
- **`README.md`** — one-line pointer to `hive/seats.md` for identity/lifecycle.
- **No change needed** to `CLAUDE.md` (it's a shim that points at `AGENTS.md` per the existing convention; it inherits the sign-off phrase list for free).

## Notes

**Doc-only ticket, but verify end-to-end.** The "done when" includes a live walk through both procedures. Reading the docs is not the same as executing them. The reviewer should bootstrap a throwaway bot and sign it off using only the docs.

**Sign-off phrase aliases.** Three is the right number — one canonical + two short alternates that read naturally. Don't sprawl into "leave the swarm", "step away", etc. — each extra alias is a parsing surface bots have to recognize correctly. If operators want a different phrase, they can edit `AGENTS.md` in their fork; the docs make clear the list is canonical for the Bot Hive reference.

**Why `HIVE.md` revision is necessary.** Today's text at `hive/HIVE.md:21–22` says "Lease / heartbeat daemon" is explicitly out of scope. The new design adds exactly that for identity (not for tickets). Without the narrow, the design contradicts the project's stated philosophy — confusing for future maintainers. The revision text from the spec keeps the file-based ticket philosophy intact while carving out identity as platform-managed.

**Out of scope:**
- Per-agent hook setup (Claude Code etc.) — HV-135.
- Migration guide for legacy bots running the old whoami — there is no migration; HV-133 is a hard cutover.
