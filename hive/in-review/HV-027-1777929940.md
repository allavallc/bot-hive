## Goal
The marketing/hero content lives at `/` (always accessible to signed-out visitors), and the nav "Sign in" button kicks off the GitHub OAuth flow from any page — no detour through `/login`.

## Why
Today `/` redirects to `/login` for signed-out users; the marketing content actually lives at `/login`. That makes the brand wordmark feel broken (clicking the logo appears to "force" you to a login page) and the nav "Sign in" link is a no-op when you're already on `/login`. Standard SaaS pattern is `/` = public marketing, sign-in = a button on every page.

## Done when
- `/` renders the existing hero content (HeroSwarm + tagline + "Sign in with GitHub" CTA) for signed-out visitors. For signed-in visitors, `/` still redirects to `/dashboard` (no behaviour change there).
- `/login` either redirects to `/` (preserves any old links) or is removed entirely.
- The nav "Sign in" button (in `src/components/page-nav.tsx`, signed-out branch) calls `authClient.signIn.social({ provider: "github", callbackURL: "/dashboard" })` directly. No more `<Link href="/login">` for the unauth state.
- The page CTA "Sign in with GitHub" continues to work as before (same OAuth call).
- Sign-out continues to redirect somewhere sensible (currently `/login`; after this ticket, redirect to `/` directly so the user lands on the public homepage).

## Desired output
A signed-out visitor lands on `/`, sees the hero, clicks either "Sign in" in the nav OR "Sign in with GitHub" on the page — both kick off the OAuth flow. No invisible no-op clicks.

## Success signals
- Brand wordmark navigates to `/` and shows hero (signed-out) or `/dashboard` (signed-in).
- Nav "Sign in" works from any signed-out page (About, Pricing, Setup, /).
- Sign-out → land on `/` with hero visible.

## Failure signals
- Hydration mismatch on `/` if the client/server splits aren't right.
- The `localStorage`-based "you've been signed out" hint disappears (it currently lives in `/login/page.tsx`). Should follow the hero into the new homepage component.

## Tests
- Manual: signed-out visitor hits `/` — hero renders, Sign in button works.
- Manual: signed-in user hits `/` — redirects to `/dashboard`.
- Manual: nav "Sign in" from /pricing or /about kicks off OAuth.
- Manual: sign out → land on `/`, hero visible.

## How to test
1. Sign out of Bot Hive on prod. Confirm you land on `/` (not `/login`) and see the hero + animation + sign-in button.
2. Click "Sign in" in the top nav. Should redirect to GitHub authorize → back to `/dashboard`.
3. Sign out again. Visit `/about`. Click "Sign in" in the top nav. Should also kick off OAuth from there.
4. Visit the old `/login` URL directly. Should redirect to `/`.

## Notes
- Implementation: extract the hero into a client component (`src/app/hero.client.tsx`), have `src/app/page.tsx` (server) check session and either redirect to `/dashboard` or render `<Hero />`. Make `src/app/login/page.tsx` a one-line redirect to `/`.
- The signed-out hint (post-sign-out "also sign out of GitHub" aside) currently shows on every visit until dismissed. Preserve current behaviour; refining it to only show post-sign-out is a follow-up polish ticket if desired.
- Out of scope: removing the `/login` route entirely (file deletion). One-line redirect is safer and cheap.

## Resolution
- New `src/app/hero.client.tsx` — client component with the hero/CTA content, OAuth-trigger button, and the post-sign-out hint (preserved as-is from `/login`).
- `src/app/page.tsx` rewritten as a server component: signed-in → `redirect("/dashboard")`; signed-out → renders `<Hero />` inside `<PageShell>`.
- `src/app/login/page.tsx` reduced to a single `redirect("/")` so any old `/login` links keep working.
- `src/components/page-nav.tsx` signed-out branch swapped from `<Link href="/login">` to a `<button>` that calls `authClient.signIn.social({ provider: "github", callbackURL: "/dashboard" })` directly. One click = OAuth flow, from any signed-out page.
- `src/lib/sign-out.ts` redirect target moved from `/login` → `/` so post-sign-out lands on the new homepage.
- Verification: typecheck + lint + 20/20 tests + `npm run build` all clean. 17 routes still compile (now `/` is dynamic instead of always-redirect).
