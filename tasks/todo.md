# Bot Hive — Phase 1 build plan

> **Phase 1 is now tracked in `hive/`.** Sub-phases 1.1–1.7 are tickets HV-001–HV-007 in `hive/backlog/`; the canonical scope and acceptance criteria live there. This file remains as the high-level plan and decision log; ticket files are the source of truth for execution.

Goal of Phase 1: a user signs in with GitHub, connects a repo that has a `hive/` folder, and sees a live kanban board of their tickets that updates within ~5 seconds of a bot pushing a commit.

Phase 1 only — channel adapters, billing, multi-user sharing all deferred.

---

## Confirmed decisions (locked in this session)

- **Stack**: Next.js (App Router, TypeScript), Better Auth, Drizzle ORM, Postgres, SSE for live updates.
- **Hosting**: local dev only. No Render config yet.
- **Repo folder Hive reads inside user repos**: `hive/`.
- **Ticket ID prefix**: `HV-XXX` (no padding, no width limit).
- **Format**: copy bot-horde verbatim — schema fields, body sections, kanban states (`backlog`, `in-progress`, `in-review`, `done`, `blocked`, `not-doing`), feature sets, acceptance loop, provenance commit trailers, design language (`#c4724a` accent, Big Shoulders Display + Atkinson Hyperlegible + Inter + JetBrains Mono).
- **Pricing rule (for later — not in Phase 1)**: ≤2 active bots per repo free; 3rd bot requires credit card; $19/mo for 3–30 bots; enterprise above. Two laptops with same Claude account count as 2 distinct bots.
- **Deletion model (for later — not in Phase 1)**: "disconnect repo ABC" with confirm dialog warning data wipe is irreversible (the GitHub repo itself is untouched).
- **Cost-tracking fields, `autonomy.ts`, `humans.yaml`, `agents/`, `log/*.jsonl`**: dropped from spec.

## Open questions (deferred — not blocking Phase 1)

### 1.2 — Database schema + first migration

Files:
- `src/db/schema.ts` — tables: `users`, `accounts`, `sessions` (Better Auth), `projects`, `tickets`, `features`, `webhook_deliveries`, `sync_state`.
- `src/db/index.ts` — Drizzle connection.
- First migration generated by `drizzle-kit`.

Schema sketch:
```
users(id, github_id, email, name, image, created_at)
projects(id, owner_id, github_repo, install_id, display_name, last_sync_sha, last_synced_at, status, created_at)
tickets(id, project_id, hv_id, state, title, frontmatter jsonb, body, file_path, file_sha, updated_at)
features(id, project_id, fs_id, title, body, file_sha, updated_at)
webhook_deliveries(delivery_id pk, project_id, received_at)  -- 7-day retention, prune job later
sync_state(project_id pk, last_sha, last_run_at)
```

Unique constraints: `(project_id, hv_id)` on tickets, `(project_id, fs_id)` on features.

Verification: migration applies clean; `psql \d tickets` shows expected columns.

### 1.5 — Project connection flow

Files:
- `src/app/projects/new/page.tsx` — "Install Hive on a repo" button that links to GitHub's install URL.
- `src/app/projects/install/callback/route.ts` — handles `?installation_id=X&setup_action=install`, writes the project row, kicks off initial sync.
- `src/lib/sync.ts` — `initialSync(projectId)`: lists files under `hive/` via GitHub Contents API, parses each ticket file (gray-matter for frontmatter + markdown body), upserts into `tickets`/`features`, records `last_sync_sha`.
- `src/lib/parse.ts` — pure functions: `parseTicket(content): Ticket`, `parseFeatureSet(content): Feature`. Reuses bot-horde field/section names exactly.

Verification: install the app on a test repo with a `hive/` folder containing a few tickets; click "Connect"; rows appear in `tickets` table within 30s; `sync_state.last_sha` matches the repo's HEAD.

(Test repo prep: I'll create a small fixture repo with 3 tickets in `hive/backlog/`, 1 in `hive/in-progress/`, 1 feature set in `hive/feature-sets/`. We use this to validate.)

### 1.6 — Webhook handler + idempotency

Files:
- `src/app/api/github/webhook/route.ts` — POST handler.
- `src/lib/webhook.ts` — HMAC verification, delivery dedupe, push-event dispatcher.

Logic:
1. Verify `X-Hub-Signature-256` against `GITHUB_APP_WEBHOOK_SECRET`. Reject 401 silently on mismatch.
2. Look up `X-GitHub-Delivery`; if seen, return 200 immediately (idempotent).
3. For `push` events: find project by installation+repo. For each commit, list files changed under `hive/` (use the commit's `added`/`modified`/`removed` arrays in the payload). Re-fetch the current contents of those files via Contents API at the new HEAD SHA. Upsert into `tickets`/`features`. Update `sync_state.last_sha`.
4. Broadcast a "project changed" event to any SSE subscribers for that project (1.7).
5. Insert into `webhook_deliveries` last (so re-delivery works if step 3 errored).

Verification: push a commit that adds/moves/deletes a ticket file in the test repo; within 10s the DB reflects it; replaying the same delivery (curl with the captured body + headers) is a no-op.

### 1.7 — Board page + SSE live updates

Files:
- `src/app/projects/[id]/page.tsx` — server component, reads tickets from DB, renders the kanban.
- `src/app/projects/[id]/board.client.tsx` — client component that subscribes to SSE and refreshes on event.
- `src/app/api/projects/[id]/stream/route.ts` — SSE endpoint.
- `src/lib/broadcast.ts` — in-memory pub/sub (Map<projectId, Set<writer>>). Restart-tolerant because clients auto-reconnect.
- `src/styles/board.css` — port of `bot-horde/board.html` styles (dark theme, accent `#c4724a`, fonts via Google Fonts, square borders, mono small-caps labels, 5-column grid).
- `src/components/ticket-card.tsx` — single card; matches bot-horde's card design (ID + title, priority/effort badges, feature-set badge, status border style).

Layout:
- 5 main columns (backlog, in-progress, in-review, done, blocked) + optional 6th (not-doing) toggleable.
- Filter bar above (priority, effort, feature set, "ready only" — same as bot-horde).
- Cards expand on click to show the full ticket body.

Verification: board renders with seeded data; pushing a commit to the test repo moves a card across columns within ~5s without manual refresh; expanded card shows Goal/Why/Done when/etc. correctly.

## Definition of Done for Phase 1

- [ ] Sign in with GitHub works.
- [ ] Connecting a repo via GitHub App install works end-to-end.
- [ ] Initial sync of a hive/-formatted repo populates the board correctly.
- [ ] Push events update the board within 10 seconds.
- [ ] Webhook is idempotent (re-delivery is a no-op).
- [ ] SSE updates work without manual refresh.
- [ ] Board visually matches `bot-horde/board.html` (dark theme, terracotta accent, mono small-caps).
- [ ] At least one realistic test repo has been driven through the full lifecycle (backlog → in-progress → in-review → done).
